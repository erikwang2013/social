## 1. লক্ষ্য ও পরিধি

ছবি+টেক্সট শর্ট-কন্টেন্ট এবং IM-কে একত্রিত একটি সোশ্যাল প্ল্যাটফর্ম তৈরি করা, যেখানে লাইভ স্ট্রিমিং (ভিডিও + দানমাকু + মাইক-লিংক), ভয়েস (মেসেজ / 1v1 কল / ভয়েস চ্যাট রুম) এবং গিফট-টিপিং ভার্চুয়াল ইকোনমি থাকবে। UI বহুভাষিকতা, কন্টেন্ট অনুবাদ এবং বহু-অঞ্চল কমপ্লায়েন্সের সমর্থন, বৈশ্বিক বহু-অঞ্চল ডিপ্লয়মেন্টসহ। তিনটি প্ল্যাটফর্মে সমান্তরাল নেটিভ ডেভেলপমেন্ট: iOS / Android / HarmonyOS।

## 2. সিস্টেম ওভারভিউ

```

              │  业务单体：认证/资料/动态/ │          (bee-rust)
```

## 3. সাবসিস্টেমগুলোর দায়িত্ব

### 3.1 contracts (gRPC কন্ট্রাক্ট, নতুন শীর্ষ-স্তরের ডিরেক্টরি)

```
contracts/
├── buf.yaml                      # buf 配置（唯一生成入口）
├── common/types.proto            # 分页、错误、时间戳、区域枚举等公共类型
├── infra/infra_service.proto     # infrastructure 对外服务
├── user/user_service.proto       # service 对外服务（admin 调用用）
└── admin/admin_service.proto     # admin 对外服务（service/infra 调用用）
```

- জেনারেশন পাইপলাইন: CI buf দিয়ে তিন ধরনের স্টাব তৈরি করে নিজ নিজ সাব-রিপোতে কমিট করে (বিল্ড নেটওয়ার্কের ওপর নির্ভর করে না)
  - service/, admin/ → PHP স্টাব (grpc/grpc + google/protobuf)
  - infrastructure/ → Rust স্টাব (tonic)
- ভার্সনিং নিয়ম: শুধু ফিল্ড যোগ করা যায়, কখনো পরিবর্তন বা মুছে ফেলা যায় না; প্যাকেজ নামে মেজর ভার্সন থাকে (`social.user.v1`)

### 3.2 service (webman v2) — ব্যবহারকারী-পক্ষের ব্যবসায়িক মনোলিথ

- **API ডোমেইন**: auth (JWT দ্বৈত টোকেন + ব্ল্যাকলিস্ট), profile, posts, likes, comments, follows, IM (কনভার্সেশন/মেসেজ/WS গেটওয়ে), notifications, অনুবাদ শিডিউলিং, লাইভ রুম/দানমাকু/মাইক-লিংক সিগন্যালিং, ভয়েস কল/ভয়েস চ্যাট রুম সিগন্যালিং, ভার্চুয়াল ইকোনমি (ওয়ালেট/গিফট/IAP যাচাই/রেভিনিউ শেয়ার), GDPR এক্সপোর্ট/ডিলিট
- **বহুভাষিক ত্রুটি ব্যবস্থা**: ত্রুটি `{code, lang_key, params}` ফেরত দেয়; টেক্সট ক্লায়েন্ট locale অনুযায়ী রেন্ডার করে
- **কিউ** (redis-queue): মডারেশন ট্রিগার, অনুবাদ শিডিউলিং, পুশ ডেলিভারি, অ্যাসিঙ্ক্রোনাস পরিসংখ্যান, গিফট-ইফেক্ট ব্রডকাস্ট
- **নির্ধারিত কাজ** (webman-crontab): অনুবাদ প্রি-ওয়ার্মিং, মেয়াদোত্তীর্ণ টোকেন/মেসেজ পরিষ্কার, অডিট আর্কাইভিং, রেভিনিউ-শেয়ার নিষ্পত্তি
- **ID**: `erikwang2013/snowflake-php` (admin-এর সাথে সামঞ্জস্যপূর্ণ)
- **কন্ট্রাক্ট**: OpenAPI 3.0 স্বয়ংক্রিয় এক্সপোর্ট → তিন প্ল্যাটফর্মের জন্য টাইপড ক্লায়েন্ট তৈরি

### 3.3 infrastructure (bee-rust) — উচ্চ-থ্রুপুট কম্পিউট লেয়ার

ব্যবসায়িক প্রাইমারি ডেটা সংরক্ষণ করে না (MySQL-ই একমাত্র সত্যের উৎস); কম্পিউট-ভারী / কোয়েরি-ভারী ক্ষমতা বহন করে:

- `bee_search`: পোস্ট/ব্যবহারকারীর ফুল-টেক্সট সার্চ (চীনা শব্দ বিভাজন, বহুভাষিক ইনডেক্সিং)
- `bee_graph`: সোশ্যাল গ্রাফ → রিকমেন্ডেশন ফিড
- `bee_tsdb`: DAU, পোস্টিং, ইন্টারঅ্যাকশন, লাইভ ভিউ, ভয়েস কল সময়কাল ইত্যাদির টাইম-সিরিজ পরিসংখ্যান
- `bee_cache/bee_kv`: টাইমলাইন ক্যাশ, কাউন্টার (লাইক সংখ্যা, ভিউ সংখ্যা, অনলাইন ব্যবহারকারী)
- অঞ্চল অনুযায়ী ডিপ্লয়; পড়া-ভারী, লেখা-হালকা; ডেটা কেন্দ্র থেকে প্রতিলিপি হয়

### 3.4 admin (open-admin পরিবর্তন)

**পুনঃব্যবহার**: JWT/RBAC/অডিট/ফাইল ম্যানেজমেন্ট/হেলথ চেক/zh-en i18n ইনফ্রাস্ট্রাকচার

**নতুন**:
- কন্টেন্ট মডারেশন ওয়ার্কবেঞ্চ: পোস্ট/কমেন্ট/ছবির দ্বিভাষিক পাশাপাশি পর্যালোচনা, বহুভাষিক প্রত্যাখ্যান-কারণ টেমপ্লেট, ব্যবহারকারী শাস্তি
- রিপোর্ট প্রসেসিং কিউ
- GDPR অনুরোধ ডেস্ক (এক্সপোর্ট/ডিলিট টিকিট)
- bee_tsdb-ভিত্তিক ডেটা ড্যাশবোর্ড
- i18n টার্ম ম্যানেজমেন্ট (চার ক্লায়েন্টের ভাগ করা টার্মের CRUD)
- গিফট ক্যাটালগ ম্যানেজমেন্ট (SKU, দাম, ইফেক্ট, বহুভাষিক নাম)
- লাইভ provider কনফিগারেশন (রাউটিং কৌশল, সুইচ ক্রম)
- উত্তোলন অনুরোধ পর্যালোচনা

### 3.5 media (স্ব-হোস্টেড মিডিয়া লেয়ার, Node.js + সিস্টেম সার্ভিস)

- `sfu/`: mediasoup; 1v1 কল এবং ভয়েস চ্যাট রুমের মিডিয়া প্লেন বহন করে; শুধু মিডিয়া ফরওয়ার্ডিং, কোনো ব্যবসায়িক লজিক নেই
- `srs/`: স্ব-হোস্টেড SRS লাইভ স্ট্রিমিং; RTMP ইনজেস্ট → FFmpeg ট্রান্সকোডিং → HTTP-FLV/HLS ডেলিভারি
- `coturn/`: TURN রিলে, NAT ট্রাভার্সালের ফলব্যাক
- সব সিগন্যালিং ফরওয়ার্ডিংয়ের জন্য service-এর WS গেটওয়ে পুনঃব্যবহার করে

### 3.6 apps — তিন প্ল্যাটফর্মে সমান্তরাল নেটিভ ডেভেলপমেন্ট

- শেয়ারড OpenAPI কন্ট্রাক্ট; প্রতিটি প্ল্যাটফর্ম নিজস্ব টাইপড ক্লায়েন্ট তৈরি করে
- ইউনিফাইড ইনফ্রাস্ট্রাকচার মডিউল: নেটওয়ার্কিং লেয়ার (রিট্রাই/অথ রিফ্রেশ), WS ক্লায়েন্ট (IM/দানমাকু/কল সিগন্যালিং), i18n (লোকাল রিসোর্স + রিমোট ইনক্রিমেন্টাল টার্ম), পুশ রেজিস্ট্রেশন, থিম
- HarmonyOS নোট: Huawei Push Kit, ArkTS কনকারেন্সি মডেল অভিযোজন

## 4. ব্যাকএন্ড কমিউনিকেশন (gRPC)

```
 service (webman/PHP) ──gRPC──▶ infrastructure (bee-rust/tonic)
      │                            ▲
      │ gRPC                        │ gRPC
      ▼                            │
 admin (webman/PHP) ──────gRPC─────┘
   （admin→service：封号/删内容/审核结果回调）
```

| কলার → ক্যালি | পেলোড |
|------|------|
| service → infra | ফুল-টেক্সট সার্চ, রিকমেন্ডেশন ফিড, টাইমলাইন হট ক্যাশ, কাউন্টার রিড/রাইট, টাইম-সিরিজ পরিসংখ্যান লেখা |
| admin → infra | ড্যাশবোর্ড পরিসংখ্যান কোয়েরি, ব্যাকএন্ড সার্চ |
| admin → service | ব্যবহারকারী শাস্তি, কন্টেন্ট মুছে ফেলা, মডারেশন ফলাফল ডেলিভারি |
| service → admin | রিপোর্ট ইভেন্ট, মডারেশন টাস্ক কিউইং (অ্যাসিঙ্ক) |

সীমা: তিন প্ল্যাটফর্মের অ্যাপ এবং অ্যাডমিন ফ্রন্টএন্ড (Flutter) HTTPS REST + WS ব্যবহার করে, gRPC স্পর্শ করে না সরাসরি।

**অপারেশনাল পূর্বশর্ত**: PHP পাশে gRPC-এর জন্য অফিসিয়াল `grpc` এক্সটেনশন (C এক্সটেনশন) + `grpc/grpc` composer প্যাকেজ প্রয়োজন; সার্ভার মোড workerman-এর অফিসিয়াল walkor/grpc পদ্ধতি অনুসরণ করে; ডিপ্লয়মেন্ট ডকুমেন্টে স্পষ্টভাবে লিখতে হবে।

## 5. বহুভাষিক আর্কিটেকচার (তিন লেয়ার)

| লেয়ার | পদ্ধতি |
|----|------|
| **UI লেয়ার** | প্রতি প্ল্যাটফর্মে locale রিসোর্স (zh/en দিয়ে শুরু; সিস্টেম যেকোনো ভাষা সমর্থন করে); সার্ভার শুধু এরর কোড + টেমপ্লেট key পাঠায় |
| **কন্টেন্ট লেয়ার** | প্রকাশের সময় মূল টেক্সট সংরক্ষণ + স্বয়ংক্রিয় ভাষা সনাক্তকরণ `lang` ফিল্ডে লেখা; পড়ার সময় reader.lang ≠ author.lang → অনুবাদ সার্ভিস (LLM/MT provider অ্যাবস্ট্রাকশন), ফলাফল Redis-এ ক্যাশ (bee_cache, TTL), `is_translated` ফ্ল্যাগ দিয়ে মূল টেক্সটে ফেরা যায়; জনপ্রিয় কন্টেন্ট নির্ধারিত সময়ে প্রি-ওয়ার্ম |
| **কমপ্লায়েন্স লেয়ার** | মডারেশন নিয়ম অঞ্চলভিত্তিক প্রযোজ্য (EU GDPR নিয়ম vs অন্যান্য অঞ্চল); দ্বিভাষিক রিপোর্ট/মডারেশন UI |

দানমাকু রিয়েল-টাইম ছোট টেক্সট: কন্টেন্ট অনুবাদ নেই, শুধু UI i18n + বহুভাষিক সংবেদনশীল-শব্দ ফিল্টারিং।

## 6. IM আর্কিটেকচার

- **গেটওয়ে**: webman WS গেটওয়ে, মাল্টি-ইনস্ট্যান্স + Redis pub/sub ক্রস-নোড ফরওয়ার্ডিং, `client_msg_id` আইডেমপোটেন্ট ডিডুপ্লিকেশন
- **ডেটা**: conversations / conversation_members / messages / message_reads; 1v1 + গ্রুপ চ্যাট (গ্রুপ সীমা 500)
- **ডেলিভারি**: অনলাইন → WS সরাসরি পুশ; অফলাইন → APNs/FCM/হুয়াওয়ে পুশ
- **ক্ষমতা**: রিড রিসিট, টাইপিং ইন্ডিকেটর, সময়-সীমিত রিকল, ইমেজ/ভয়েস মেসেজ (S3 আপলোড + ট্রান্সকোডিং)
- ফিডের সাথে ইউজার সিস্টেম এবং নোটিফিকেশন সিস্টেম ভাগ করে

## 7. লাইভ স্ট্রিমিং আর্কিটেকচার (ভিডিও + দানমাকু + মাইক-লিংক, দ্বৈত ট্র্যাক)

### 7.1 Provider অ্যাবস্ট্রাকশন (service-এর ভেতরে)

```
LiveProvider 接口（admin 可配置）
├── provider_3rd   → 第三方直播云（默认主力）：推流/转码/CDN 分发/实时审核
└── provider_self  → 自建 SRS：推流/FFmpeg 转码/自有分发（审核调第三方审核 API）
```

| প্রক্রিয়া | নকশা |
|------|------|
| রাউটিং কৌশল | রুম তৈরি করার সময় অঞ্চলভিত্তিক ডিফল্ট provider নির্বাচন (admin কনফিগারযোগ্য ওভাররাইড); তৃতীয়-পক্ষ কভারেজ নেই বা খরচ-সংবেদনশীল অঞ্চল → স্ব-হোস্টেড |
| ব্যর্থতা ফেলওভার | ব্রডকাস্টার SDK দ্বৈত ইনজেস্ট (প্রাইমারি = তৃতীয় পক্ষ, ব্যাকআপ = স্ব-হোস্টেড SRS); প্লেয়ার provider অনুযায়ী URL সমাধান করে, তৃতীয় পক্ষের ব্যর্থতায় স্বয়ংক্রিয়ভাবে স্ব-হোস্টেড স্ট্রিমে স্যুইচ |
| দানমাকু/মাইক-লিংক | ভিডিও পাইপলাইন থেকে ডিকাপলড: দানমাকু service WS দিয়ে, মাইক-লিংক তৃতীয়-পক্ষ RTC দিয়ে |
| কমপ্লায়েন্স | স্ব-হোস্টেড পাইপলাইনের রিয়েল-টাইম অডিও/ভিডিও মডারেশন তৃতীয়-পক্ষ মডারেশন API পুনঃব্যবহার করে (শুধু মডারেশন কেনা হয়, ট্রান্সপোর্ট নয়) |

### 7.2 লাইভ রুম

রুম CRUD, স্ট্রিম শুরু/শেষ স্টেট মেশিন, কভার, ঘোষণা (বহুভাষিক), ভিউ কাউন্ট (bee_tsdb), দানমাকু রুম চ্যানেল (Redis pub/sub), মাইক-লিংক রোল ম্যানেজমেন্ট (হোস্ট/মাইক-লিংক সিট, service তৃতীয়-পক্ষ RTC টোকেন ইস্যু করে), অনলাইন/পিক/সময়কাল পরিসংখ্যান → admin ড্যাশবোর্ড।

## 9. ভার্চুয়াল ইকোনমি (টপ-আপ + গিফট-টিপিং + উত্তোলন)

```
国内：微信支付 / 支付宝（APP/H5）          ├─▶ PaymentProvider ─▶ 钱包
国外：微信国际 / 支付宝国际 / Stripe / PayPal│    （按 region 选路）
                                          └─▶ payments 支付单（幂等+验签+对账）

                         直播间特效事件广播(WS)→主播收入入账(分成)
主播钱包 ──▶ payouts 提现单 ──▶ 国内：商家转账 │ 国外：Stripe Connect/PayPal
```

### 9.1 পেমেন্ট চ্যানেল (দেশীয় vs আন্তর্জাতিক)

```
PaymentProvider 接口（admin 配置）
├── 国内（CNY）
│   ├── wechat_cn    微信支付（APP/H5）
│   ├── alipay_cn    支付宝（APP/WAP）
│   └── 提现：商家转账（零钱/银行卡）
├── 国外（USD/EUR/...）
│   ├── wechat_global  微信国际支付（境外商户）
│   ├── alipay_global  支付宝国际（Alipay+）
│   ├── stripe         卡 / Apple Pay / Google Pay / SEPA
│   ├── paypal
│   └── 提现：Stripe Connect / PayPal 批量打款
└── 移动端虚拟币充值：App Store / Google Play / 华为 IAP（商店政策强制，服务端凭证校验）
```

| প্রক্রিয়া | নকশা |
|------|------|
| চ্যানেল রাউটিং | ব্যবহারকারীর region + মুদ্রা + admin মার্চেন্ট নিয়ম অনুযায়ী চ্যানেল নির্বাচন, কনফিগারযোগ্য ফলব্যাক ক্রম (দেশীয়/আন্তর্জাতিক স্বাভাবিকভাবে বিভক্ত) |
| পেমেন্ট অর্ডার | ইউনিফাইড payments মডেল: ব্যবহারকারী/চ্যানেল/পরিমাণ/মুদ্রা/স্টেট মেশিন, সব চ্যানেলে আইডেমপোটেন্ট |
| কলব্যাক | ইউনিফাইড সিগনেচার যাচাই র্যাপার (RSA/HMAC), আইডেমপোটেন্ট কলব্যাক, দৈনিক মিলান কাজ (চ্যানেল স্টেটমেন্ট যাচাই) |
| উত্তোলন | payouts অর্ডার: দেশীয় মার্চেন্ট ট্রান্সফার, আন্তর্জাতিক Stripe Connect/PayPal পেমেন্ট; চ্যানেল ক্ষমতা অনুযায়ী স্প্লিট/পেআউট মোড |
| মূল্য নির্ধারণ | আঞ্চলিক মূল্য টেবিল (admin): ভার্চুয়াল মুদ্রা × মুদ্রার দাম, কেন্দ্রীয়ভাবে ব্যবস্থাপিত বিনিময় হার |
| ঝুঁকি নিয়ন্ত্রণ | সীমা/ফ্রিকোয়েন্সি ক্যাপ/অস্বাভাবিক অর্ডার অ্যালার্ট, সম্পূর্ণ লেনদেন অডিট (অডিট সিস্টেম পুনঃব্যবহার) |
| গিফট SKU | গিফট ক্যাটালগ (দাম, ইফেক্ট আইডেন্টিফায়ার, বহুভাষিক নাম) admin দ্বারা পরিচালিত |

কমপ্লায়েন্স: মোবাইলে ভার্চুয়াল-মুদ্রা টপ-আপ অবশ্যই স্টোর IAP দিয়ে যেতে হবে (Apple/Google/হুয়াওয়ে কমিশন); WeChat/Alipay ব্যবহার হয় H5/Web এবং নির্দিষ্ট আঞ্চলিক পরিস্থিতিতে; উত্তোলনে ফান্ড সেটেলমেন্ট জড়িত, তাই প্ল্যাটফর্ম লাইসেন্সপ্রাপ্ত চ্যানেলের স্প্লিট/পেআউট ইন্টারফেস দিয়ে সেগুলো সমাধান করে; চ্যানেল চুক্তির যোগ্যতা M6b-এর আগে নিশ্চিত করতে হবে; নাবালকদের সীমা কমপ্লায়েন্স পর্যায়ে যায়।

## 12. ডিপ্লয়মেন্ট ও অপারেশন (বৈশ্বিক বহু-অঞ্চল)

- **প্রাথমিক আর্কিটেকচার**: দুটি বড় অঞ্চল — চীন + বিদেশ; প্রতিটি অঞ্চলে webman ক্লাস্টার + bee-rust ক্লাস্টার + লোকাল Redis + media (SFU/SRS/TURN); MySQL কেন্দ্রীয় প্রাইমারি + প্রতি-অঞ্চল রিড-অনলি রেপ্লিকা; CDN অঞ্চলভিত্তিক
- **WS নিকটতম-অঞ্চল সংযোগ**, ক্রস-অঞ্চল মেসেজ কেন্দ্রীয়ভাবে সমন্বিত; পুশ অঞ্চলভিত্তিক সংশ্লিষ্ট ভেন্ডর দিয়ে
- **বিবর্তন পথ**: ট্রাফিক বৃদ্ধির পর ইউজার হ্যাশ দিয়ে ডেটাবেস শার্ডিং
- **মনিটরিং**: Prometheus মেট্রিক্স (open-admin প্যাটার্ন অনুসরণ), কেন্দ্রীভূত লগ, অ্যালার্ট (এরর রেট/লেটেন্সি/কিউ ব্যাকলগ/মিডিয়া সার্ভিস স্বাস্থ্য)

## 13. নিরাপত্তা ও কমপ্লায়েন্স

- service open-admin-এর 18-লেয়ার ডিফেন্স প্যাটার্ন প্রতিলিপি করে (XSS/SQLi/CSRF/রেট লিমিটিং/CSP)

### 16.4 নিয়োগের অগ্রাধিকার

1. ব্যাকএন্ড PHP ×2 + টেক লিড (ভিত্তি পর্বের মূল; ব্যাকএন্ড সবচেয়ে বড় কাজের ক্ষেত্র)
2. মোবাইল ×3 (তিন প্ল্যাটফর্ম সমান্তরালতা মোট সময়সীমার কঠিন বাধা — যত তাড়াতাড়ি, তত ভালো)
3. UI/UX, QA
4. Rust, DevOps (M1–M2-এর আগে যোগদান)
5. অডিও/ভিডিও (M3-এর শেষ)
6. পেমেন্ট/কমপ্লায়েন্স অ্যাডভাইজার, লোকালাইজেশন (M6/M7-এ প্রয়োজনে)

### 16.5 ঝুঁকি ও ফলব্যাক

- অডিও/ভিডিও এবং পেমেন্ট চ্যানেল নিয়োগের জন্য সবচেয়ে কঠিন দুটি ভূমিকা (বিশেষজ্ঞ দুষ্প্রাপ্য); আউটসোর্সিং/অ্যাডভাইজার ফলব্যাক পরিকল্পনা রাখুন
