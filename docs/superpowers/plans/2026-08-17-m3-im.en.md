# M3 IM Milestone Implementation Plan (P1: Text + Image Message Closed Loop)

**语言 / Languages:** [中文](2026-08-17-m3-im.md) · [English](2026-08-17-m3-im.en.md) · [한국어](2026-08-17-m3-im.ko.md) · [Русский](2026-08-17-m3-im.ru.md) · [Deutsch](2026-08-17-m3-im.de.md) · [Français](2026-08-17-m3-im.fr.md) · [Español](2026-08-17-m3-im.es.md) · [Português](2026-08-17-m3-im.pt.md) · [हिन्दी](2026-08-17-m3-im.hi.md) · [العربية](2026-08-17-m3-im.ar.md) · [বাংলা](2026-08-17-m3-im.bn.md) · [Bahasa Indonesia](2026-08-17-m3-im.id.md) · [日本語](2026-08-17-m3-im.ja.md)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver M3 P1: private chat + group chat text/image message closed loop — WS gateway (webman ws worker + Redis pub/sub cross-node), four-table data model, writes over WS / reads over REST, online direct push + offline queue + polling fallback, three-platform WS client integration.

**Architecture:** service (webman) adds a ws worker (8789), connection registration double-writes to Redis (`ws:conn:{fd}` TTL 60s + `ws:user:{uid}` node index) + in-worker memory Map; channels are per-user `im:user:{uid}` cross-node pub/sub. Write paths all go over WS (send/read/typing/recall), read paths via REST (conversations/history pagination). Delivery: online direct push + offline queue `im:offline:{uid}` (cap 200) + `PushProvider` interface (M3 uses NullProvider, polling fallback). Message idempotency: SETNX `im:dedup:{uid}:{client_msg_id}` TTL 24h + DB unique index. **No im proto needed** (no cross-service calls, gRPC is only an M2 asset).

**Tech Stack:** PHP 8.3 / webman 2.x / workerman ws / Redis (webman/redis plugin) / Eloquent / sqlite :memory: tests; Android OkHttp WebSocket + kotlinx.serialization; iOS URLSessionWebSocketTask; HarmonyOS @ohos.net.webSocket.

**Confirmed decisions:** Push strategy = NullProvider + in-app notifications + polling fallback (user-approved); voice/calls/multi-device multi-connection deferred to M4.

- [ ] **Step 2: ConnectionRegistry (local connection table + Redis registration)**

Static class. `Map<int fd, int uid>` (memory) + `Map<int uid, int fd>` single-connection policy. Methods:
- `attach(int $fd, int $uid)`: if the uid already has an old fd → return the old fd for kick-out (push `kicked` frame + close), then register the new fd; Redis writes `ws:conn:{fd}` = uid (EXPIRE 60) and `ws:user:{uid}` = this node's identifier (node id uses `gethostname().':'.posix_getpid()` or `im.node_id` in config, EXPIRE 60 on write).
- `detach(int $fd)`: remove from memory + Redis DEL `ws:conn:{fd}`; if `ws:user:{uid}` points to this node, DEL it.
- `localFd(int $uid): ?int`: memory lookup.
- `heartbeat(int $fd, int $uid)`: renew the EXPIRE of `ws:conn:{fd}` and `ws:user:{uid}`.
- Redis uses `support\Redis` (webman redis plugin, see the existing `app/queue/redis` usage).
- The node identifier is taken from `ws.constructor.node_id` in `config/process.php` (default `gethostname()`, changeable).

- [ ] **Step 3: WsServer (Worker handler)**

Extends `Workerman\Worker` (see the webman plugin/official ws example): `onConnect` empty implementation; in `onWebSocketConnect` (registered as a static method after worker construction) parse `$_GET['token']` → `JwtHelper::decode` (see `app/middleware/AuthMiddleware.php` usage, close(4001) on failure); on success `ConnectionRegistry::attach` and return a `{type:'ready'}` frame. `onMessage` delegates to ActionHandler (Task 4); `onClose` calls `detach`. `onWorkerStart` registers the Redis subscription callback (`im:user:{uid}` dynamic subscription, Task 5 Deliverer's responsibility) — Task 3 only implements the connection lifecycle; message handling is left for Task 4.

- [ ] **Step 1: Envelope (envelope parse/serialize)**

Incoming frame JSON `{type, seq, data}`; outgoing frame `{type, seq?, data}`. `Envelope::decode(string $raw): ?array` (json failure/missing type returns null); `Envelope::encode(string $type, array $data, ?int $seq=null): string`. Constants: `T_SEND='send' T_ACK='ack' T_READ='read' T_TYPING='typing' T_RECALL='recall' T_PING='ping'`; `T_MESSAGE='message' T_KICKED='kicked' T_PONG='pong' T_ERROR='error'`.

- [ ] **Step 2: ActionHandler::handle(int $fd, int $uid, array $env): void**

Dispatch by `$env['type']`, unknown types return `{type:'error', data:{msg:'unknown type'}}`:
- `ping` → return `pong` (seq echo); `ConnectionRegistry::heartbeat($fd,$uid)`.
- `send` → validate `data.{conversation_id, client_msg_id}` and at least one of `content|image_url` (missing → error); idempotency: `Redis::set('im:dedup:'.$uid.':'.$cmid, '1', 'EX', 86400, 'NX')`, on false → query the DB and return `{type:'ack', data:{client_msg_id, message_id}}` then return; persist (`Message::create`, DB unique index as fallback — on conflict return the ack with the existing id) → `Deliverer::deliver($msg, $uid)` (Task 5) → return `{type:'ack', data:{client_msg_id, message_id}}`.
- `read` → validate conversation_id; `MessageRead::advance($cid,$uid,$data.last_read_id)`; `Deliverer::notifyRead($cid,$uid,$lastReadId)`.
- `typing` → `Deliverer::relayTyping($cid,$uid)` (pure relay, no persistence).
- `recall` → validate message_id and that the sender is self; `Message::where('id',..)->where('sender_id',$uid)->first()`, reject if `created_at` is >120s ago (error); `update(['recall_status'=>1,'recall_at'=>now])`; `Deliverer::notifyRecall($cid,$mid,$uid)`.

### Task 5: Delivery — online direct push / offline queue / PushProvider abstraction

- [ ] **Step 1: PushProvider interface + NullPushProvider**

```php
interface PushProvider { public function send(int $uid, array $payload): void; }
class NullPushProvider implements PushProvider { public function send(int $uid, array $payload): void {} }
```

Factory in Deliverer: `push()` takes the implementation from config or a static map (M3 fixed NullPushProvider; `ponytail: vendor integration only needs an implementation class + factory branch`).

- [ ] **Step 2: Deliverer (cross-node delivery core)**

Static methods:
- `deliver(Message $msg, int $senderId): void`: get `ConversationMember::where('conversation_id',$msg->conversation_id)->where('status',1)->pluck('user_id')`; for each member:
  - `ConnectionRegistry::localFd($uid)` hit → push `{type:'message', data:{...msg fields..., sender_id}}` via `sendToFd` in that worker;
  - miss → `Redis::publish('im:user:'.$uid, json_encode([...]))` (other nodes push directly after subscribing and checking the local Map); no one subscribed to the channel → `Redis::rpush('im:offline:'.$uid, $payload)` + `LTRIM` cap 200.
  - After offline enqueue, call `PushProvider::send($uid, payload)` (M3 Null no-op).
  - Node subscription management: `bootstrap(int $workerFd)` uses `\Workerman\Timer` every 5s to differentially subscribe to the channels of local online users for `im:user:*` (use the `Redis::subscribe` callback pushing to the local fd — see the workerman Redis subscription example). The subscription callback receives the `im:user:{uid}` message → if `localFd($uid)` hits push directly, otherwise ignore (the sender already wrote the offline queue).
- `notifyRead(int $cid, int $uid, int $lastReadId): void`: publish to each member's channel `{type:'read', data:{conversation_id,user_id,last_read_id}}` (online push, no offline persistence — read semantics are DB-based, refetched on reconnect).
- `relayTyping(int $cid, int $uid): void`: publish to each member `{type:'typing', data:{conversation_id,user_id}}`, only push to members `!= $uid`.
- `notifyRecall(int $cid, int $mid, int $uid): void`: publish `{type:'recall', data:{conversation_id,message_id,user_id}}`, offline members also enqueue to `im:offline:{uid}` (recall notifications need offline delivery).
