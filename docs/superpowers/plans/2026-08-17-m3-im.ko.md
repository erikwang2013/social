# M3 IM 마일스톤 구현 계획 (P1: 텍스트+이미지 메시지 클로즈드 루프)

**语言 / Languages:** [中文](2026-08-17-m3-im.md) · [English](2026-08-17-m3-im.en.md) · [한국어](2026-08-17-m3-im.ko.md) · [Русский](2026-08-17-m3-im.ru.md) · [Deutsch](2026-08-17-m3-im.de.md) · [Français](2026-08-17-m3-im.fr.md) · [Español](2026-08-17-m3-im.es.md) · [Português](2026-08-17-m3-im.pt.md) · [हिन्दी](2026-08-17-m3-im.hi.md) · [العربية](2026-08-17-m3-im.ar.md) · [বাংলা](2026-08-17-m3-im.bn.md) · [Bahasa Indonesia](2026-08-17-m3-im.id.md) · [日本語](2026-08-17-m3-im.ja.md)

> **에이전트 워커용:** 필수 하위 스킬: superpowers:subagent-driven-development(권장) 또는 superpowers:executing-plans를 사용하여 이 계획을 태스크별로 구현하세요. 단계는 체크박스(`- [ ]`) 구문으로 추적합니다.

**목표:** M3 P1 제공: 1:1 채팅+그룹 채팅의 텍스트/이미지 메시지 클로즈드 루프 — WS 게이트웨이(webman ws worker + Redis pub/sub 크로스 노드), 네 개 테이블 데이터 모델, 쓰기는 WS / 읽기는 REST, 온라인 직접 푸시 + 오프라인 큐 + 폴링 폴백, 삼단 WS 클라이언트 연동.

**아키텍처:** service(webman)에 ws worker(8789) 추가, 연결 등록은 Redis에 이중 기록(`ws:conn:{fd}` TTL 60초 + `ws:user:{uid}` 노드 인덱스) + 워커 내 메모리 Map; 채널은 사용자별 `im:user:{uid}` 크로스 노드 pub/sub. 쓰기 경로는 전부 WS(send/read/typing/recall), 읽기 경로는 REST(대화/히스토리 페이지네이션). 배달: 온라인 직접 푸시 + 오프라인 큐 `im:offline:{uid}`(상한 200) + `PushProvider` 인터페이스(M3은 NullProvider 사용, 폴링 폴백). 메시지 멱등성: SETNX `im:dedup:{uid}:{client_msg_id}` TTL 24시간 + DB 고유 인덱스. **im proto 불필요**(크로스 서비스 호출 없음, gRPC는 M2 자산일 뿐).

**기술 스택:** PHP 8.3 / webman 2.x / workerman ws / Redis(webman/redis 플러그인) / Eloquent / sqlite :memory: 테스트; Android OkHttp WebSocket + kotlinx.serialization; iOS URLSessionWebSocketTask; HarmonyOS @ohos.net.webSocket.

**확정된 결정:** 푸시 전략 = NullProvider + 앱 내 알림 + 폴링 폴백(사용자 승인); 음성/통화/다중 기기 다중 연결은 M4로 후순위.

- [ ] **Step 2: ConnectionRegistry(로컬 연결 테이블 + Redis 등록)**

정적 클래스. `Map<int fd, int uid>`(메모리) + `Map<int uid, int fd>` 단일 연결 정책. 메서드:
- `attach(int $fd, int $uid)`: 해당 uid에 기존 fd가 있으면 → 기존 fd 반환해 킥아웃(`kicked` 프레임 푸시 + close), 이후 새 fd 등록; Redis에 `ws:conn:{fd}` = uid(EXPIRE 60)와 `ws:user:{uid}` = 이 노드 식별자(노드 id는 `gethostname().':'.posix_getpid()` 또는 config의 `im.node_id` 사용, 쓰기 시 EXPIRE 60).
- `detach(int $fd)`: 메모리 제거 + Redis DEL `ws:conn:{fd}`; `ws:user:{uid}`가 이 노드를 가리키면 DEL.
- `localFd(int $uid): ?int`: 메모리 조회.
- `heartbeat(int $fd, int $uid)`: `ws:conn:{fd}`와 `ws:user:{uid}`의 EXPIRE 갱신.
- Redis는 `support\Redis` 사용(webman redis 플러그인, 기존 `app/queue/redis` 사용 방식 참조).
- 이 노드 식별자는 `config/process.php`의 `ws.constructor.node_id`에서 가져옴(기본 `gethostname()`, 변경 가능).

- [ ] **Step 1: Envelope(봉투 파싱/직렬화)**

수신 프레임 JSON `{type, seq, data}`; 송신 프레임 `{type, seq?, data}`. `Envelope::decode(string $raw): ?array`(json 실패/type 없음 → null 반환); `Envelope::encode(string $type, array $data, ?int $seq=null): string`. 상수: `T_SEND='send' T_ACK='ack' T_READ='read' T_TYPING='typing' T_RECALL='recall' T_PING='ping'`; `T_MESSAGE='message' T_KICKED='kicked' T_PONG='pong' T_ERROR='error'`.

- [ ] **Step 2: ActionHandler::handle(int $fd, int $uid, array $env): void**

`$env['type']`로 디스패치, 알 수 없는 타입은 `{type:'error', data:{msg:'unknown type'}}` 반환:
- `ping` → `pong` 반환(seq 에코); `ConnectionRegistry::heartbeat($fd,$uid)`.
- `send` → `data.{conversation_id, client_msg_id}`와 `content|image_url` 중 하나 이상 검증(없으면 → error); 멱등성: `Redis::set('im:dedup:'.$uid.':'.$cmid, '1', 'EX', 86400, 'NX')`, false → DB 조회 후 `{type:'ack', data:{client_msg_id, message_id}}` 반환하고 종료; 저장(`Message::create`, DB 고유 인덱스 폴백 — 충돌 시 기존 id로 ack 반환) → `Deliverer::deliver($msg, $uid)`(Task 5) → `{type:'ack', data:{client_msg_id, message_id}}` 반환.
- `read` → conversation_id 검증; `MessageRead::advance($cid,$uid,$data.last_read_id)`; `Deliverer::notifyRead($cid,$uid,$lastReadId)`.
- `typing` → `Deliverer::relayTyping($cid,$uid)`(순수 중계, 저장 없음).
- `recall` → message_id와 발신자 본인 검증; `Message::where('id',..)->where('sender_id',$uid)->first()`, `created_at`이 120초 초과면 거부(error); `update(['recall_status'=>1,'recall_at'=>now])`; `Deliverer::notifyRecall($cid,$mid,$uid)`.

- [ ] **Step 1: PushProvider 인터페이스 + NullPushProvider**

```php
interface PushProvider { public function send(int $uid, array $payload): void; }
class NullPushProvider implements PushProvider { public function send(int $uid, array $payload): void {} }
```

팩토리는 Deliverer에: `push()`는 config 또는 정적 map에서 구현체를 가져옴(M3은 NullPushProvider 고정; `ponytail: 벤더 연동은 구현 클래스 + 팩토리 분기만 추가하면 됨`).

- [ ] **Step 2: Deliverer(크로스 노드 배달 코어)**

정적 메서드:
- `deliver(Message $msg, int $senderId): void`: `ConversationMember::where('conversation_id',$msg->conversation_id)->where('status',1)->pluck('user_id')` 조회; 각 멤버마다:
  - `ConnectionRegistry::localFd($uid)` 히트 → 해당 워커 내에서 `sendToFd`로 `{type:'message', data:{...msg 필드..., sender_id}}` 푸시;
  - 미스 → `Redis::publish('im:user:'.$uid, json_encode([...]))`(다른 노드가 구독 후 로컬 Map 확인하여 직접 푸시); 채널 구독자 없음 → `Redis::rpush('im:offline:'.$uid, $payload)` + `LTRIM` 상한 200.
  - 오프라인 큐 등록 후 `PushProvider::send($uid, payload)` 호출(M3 Null은 무작동).
  - 노드 구독 관리: `bootstrap(int $workerFd)`는 `\Workerman\Timer`로 5초마다 `im:user:*`에 대해 이 노드 온라인 사용자 채널을 차등 구독(`Redis::subscribe` 콜백으로 로컬 fd에 푸시 — workerman Redis 구독 예제 참조). 구독 콜백이 `im:user:{uid}` 메시지를 받으면 → `localFd($uid)` 히트 시 직접 푸시, 아니면 무시(발신자가 이미 오프라인 큐에 기록).
- `notifyRead(int $cid, int $uid, int $lastReadId): void`: 각 멤버 채널에 `{type:'read', data:{conversation_id,user_id,last_read_id}}` publish(온라인 푸시, 오프라인 저장 없음 — 읽음 의미는 DB 기준, 재연결 시 다시 조회).
- `relayTyping(int $cid, int $uid): void`: 각 멤버에 `{type:'typing', data:{conversation_id,user_id}}` publish, 멤버 `!= $uid`인 경우에만 푸시.
- `notifyRecall(int $cid, int $mid, int $uid): void`: `{type:'recall', data:{conversation_id,message_id,user_id}}` publish, 오프라인 멤버도 `im:offline:{uid}`에 저장(리콜 알림은 오프라인 배달 필요).

- [ ] **Step 3: DelivererTest(통합 테스트: 메모리 경로)**
