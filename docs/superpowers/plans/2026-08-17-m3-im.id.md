# Rencana Implementasi Milestone M3 IM (P1: Loop Tertutup Pesan Teks + Gambar)

**语言 / Languages:** [中文](2026-08-17-m3-im.md) · [English](2026-08-17-m3-im.en.md) · [한국어](2026-08-17-m3-im.ko.md) · [Русский](2026-08-17-m3-im.ru.md) · [Deutsch](2026-08-17-m3-im.de.md) · [Français](2026-08-17-m3-im.fr.md) · [Español](2026-08-17-m3-im.es.md) · [Português](2026-08-17-m3-im.pt.md) · [हिन्दी](2026-08-17-m3-im.hi.md) · [العربية](2026-08-17-m3-im.ar.md) · [বাংলা](2026-08-17-m3-im.bn.md) · [Bahasa Indonesia](2026-08-17-m3-im.id.md) · [日本語](2026-08-17-m3-im.ja.md)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Tujuan:** Mengirimkan M3 P1: loop tertutup pesan teks/gambar di chat privat + grup — gateway WS (webman ws worker + Redis pub/sub lintas node), model data empat tabel, tulis melalui WS / baca melalui REST, push langsung online + antrean offline + fallback polling, integrasi klien WS tiga platform.

**Arsitektur:** service (webman) menambahkan ws worker (8789), pendaftaran koneksi menulis ganda ke Redis (`ws:conn:{fd}` TTL 60s + indeks node `ws:user:{uid}`) + Map memori worker; kanal bersifat per-pengguna `im:user:{uid}` pub/sub lintas node. Semua jalur tulis melalui WS (send/read/typing/recall), jalur baca melalui REST (percakapan/paginasi riwayat). Pengiriman: push langsung online + antrean offline `im:offline:{uid}` (cap 200) + antarmuka `PushProvider` (di M3, NullProvider, fallback polling). Idempotensi pesan: SETNX `im:dedup:{uid}:{client_msg_id}` TTL 24h + indeks unik DB. **Tidak perlu im proto** (tidak ada panggilan lintas layanan, gRPC hanya aset M2).

**Tumpukan Teknologi:** PHP 8.3 / webman 2.x / workerman ws / Redis (plugin webman/redis) / Eloquent / tes sqlite :memory:; Android OkHttp WebSocket + kotlinx.serialization; iOS URLSessionWebSocketTask; HarmonyOS @ohos.net.webSocket.

**Keputusan terkonfirmasi:** Strategi push = NullProvider + notifikasi in-app + fallback polling (disetujui pengguna); suara/panggilan/multi-perangkat multi-koneksi ditunda ke M4.

- [ ] **Langkah 2: ConnectionRegistry (tabel koneksi lokal + pendaftaran Redis)**

Kelas statis. `Map<int fd, int uid>` (memori) + `Map<int uid, int fd>` kebijakan koneksi tunggal. Metode:
- `attach(int $fd, int $uid)`: jika uid sudah punya fd lama → kembalikan fd lama untuk kick-out (push frame `kicked` + close), lalu daftarkan fd baru; tulis ke Redis `ws:conn:{fd}` = uid (EXPIRE 60) dan `ws:user:{uid}` = identitas node ini (node id via `gethostname().':'.posix_getpid()` atau `im.node_id` di config, EXPIRE 60 saat menulis).
- `detach(int $fd)`: hapus dari memori + Redis DEL `ws:conn:{fd}`; jika `ws:user:{uid}` menunjuk ke node ini, DEL.
- `localFd(int $uid): ?int`: pencarian memori.
- `heartbeat(int $fd, int $uid)`: perpanjang EXPIRE `ws:conn:{fd}` dan `ws:user:{uid}`.
- Redis via `support\Redis` (plugin webman redis, lihat penggunaan `app/queue/redis` yang ada).
- Identitas node diambil dari `ws.constructor.node_id` di `config/process.php` (default `gethostname()`, bisa diubah).

- [ ] **Langkah 1: Antarmuka PushProvider + NullPushProvider**

```php
interface PushProvider { public function send(int $uid, array $payload): void; }
class NullPushProvider implements PushProvider { public function send(int $uid, array $payload): void {} }
```

Factory di Deliverer: `push()` mengambil implementasi dari config atau map statis (di M3 tetap NullPushProvider; `ponytail: integrasi vendor hanya perlu kelas implementasi + cabang factory`).

- [ ] **Langkah 2: Deliverer (inti pengiriman lintas node)**

Metode statis:
- `deliver(Message $msg, int $senderId): void`: ambil `ConversationMember::where('conversation_id',$msg->conversation_id)->where('status',1)->pluck('user_id')`; untuk setiap anggota:
  - `ConnectionRegistry::localFd($uid)` kena → di worker itu push `{type:'message', data:{...bidang msg..., sender_id}}` via `sendToFd`;
  - tidak kena → `Redis::publish('im:user:'.$uid, json_encode([...]))` (node lain setelah berlangganan cek Map lokal lalu push langsung); tidak ada yang berlangganan kanal → `Redis::rpush('im:offline:'.$uid, $payload)` + `LTRIM` cap 200.
  - Setelah antrean offline, panggil `PushProvider::send($uid, payload)` (di M3, Null tanpa operasi).
  - Manajemen langganan node: `bootstrap(int $workerFd)` menggunakan `\Workerman\Timer` tiap 5s untuk berlangganan diferensial ke kanal pengguna online lokal pada `im:user:*` (gunakan callback `Redis::subscribe` yang push ke fd lokal — lihat contoh langganan Redis workerman). Callback langganan menerima pesan `im:user:{uid}` → jika `localFd($uid)` kena push langsung, jika tidak abaikan (pengirim sudah menulis antrean offline).
- `notifyRead(int $cid, int $uid, int $lastReadId): void`: publish ke kanal setiap anggota `{type:'read', data:{conversation_id,user_id,last_read_id}}` (push online, tanpa persistensi offline — semantik baca berbasis DB, ditarik ulang saat reconnect).
- `relayTyping(int $cid, int $uid): void`: publish ke setiap anggota `{type:'typing', data:{conversation_id,user_id}}`, hanya push ke anggota `!= $uid`.
- `notifyRecall(int $cid, int $mid, int $uid): void`: publish `{type:'recall', data:{conversation_id,message_id,user_id}}`, anggota offline juga masuk `im:offline:{uid}` (notifikasi recall butuh pengiriman offline).
