**语言 / Languages:** [中文](2026-08-17-m3-im.md) · [English](2026-08-17-m3-im.en.md) · [한국어](2026-08-17-m3-im.ko.md) · [Русский](2026-08-17-m3-im.ru.md) · [Deutsch](2026-08-17-m3-im.de.md) · [Français](2026-08-17-m3-im.fr.md) · [Español](2026-08-17-m3-im.es.md) · [Português](2026-08-17-m3-im.pt.md) · [हिन्दी](2026-08-17-m3-im.hi.md) · [العربية](2026-08-17-m3-im.ar.md) · [বাংলা](2026-08-17-m3-im.bn.md) · [Bahasa Indonesia](2026-08-17-m3-im.id.md) · [日本語](2026-08-17-m3-im.ja.md)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** Поставить M3 P1: замкнутый цикл текстовых/графических сообщений в личных чатах и группах — WS-шлюз (webman ws worker + Redis pub/sub между узлами), модель данных из четырёх таблиц, запись через WS / чтение через REST, онлайн-пуш напрямую + очередь офлайн + деградация до опроса, интеграция WS-клиентов на трёх платформах.

**Архитектура:** service (webman) добавляет ws worker (8789), регистрация соединений пишет в Redis двойную запись (`ws:conn:{fd}` TTL 60s + индекс узла `ws:user:{uid}`) + Map в памяти worker; каналы — per-user `im:user:{uid}` pub/sub между узлами. Все пути записи идут через WS (send/read/typing/recall), пути чтения — через REST (беседы/пагинация истории). Доставка: онлайн-пуш напрямую + очередь офлайн `im:offline:{uid}` (cap 200) + интерфейс `PushProvider` (в M3 — NullProvider, деградация до опроса). Идемпотентность сообщений: SETNX `im:dedup:{uid}:{client_msg_id}` TTL 24h + уникальный индекс БД. **im proto не нужен** (нет межсервисных вызовов, gRPC — только актив M2).

**Технологический стек:** PHP 8.3 / webman 2.x / workerman ws / Redis (плагин webman/redis) / Eloquent / sqlite :memory: тесты; Android OkHttp WebSocket + kotlinx.serialization; iOS URLSessionWebSocketTask; HarmonyOS @ohos.net.webSocket.

**Подтверждённые решения:** Стратегия пушей = NullProvider + внутриприложные уведомления + деградация до опроса (утверждено пользователем); голосовые сообщения/звонки/многоплатформенные мультиподключения отложены до M4.

- [ ] **Шаг 2: ConnectionRegistry (таблица локальных соединений + регистрация в Redis)**

Статический класс. `Map<int fd, int uid>` (память) + `Map<int uid, int fd>` политика одиночного соединения. Методы:
- `attach(int $fd, int $uid)`: если у uid уже есть старый fd → вернуть старый fd для выталкивания (отправить фрейм `kicked` + close), затем зарегистрировать новый fd; в Redis записать `ws:conn:{fd}` = uid (EXPIRE 60) и `ws:user:{uid}` = идентификатор данного узла (node id через `gethostname().':'.posix_getpid()` или `im.node_id` из конфига, при записи EXPIRE 60).
- `detach(int $fd)`: удалить из памяти + Redis DEL `ws:conn:{fd}`; если `ws:user:{uid}` указывает на данный узел — DEL.
- `localFd(int $uid): ?int`: поиск в памяти.
- `heartbeat(int $fd, int $uid)`: продлить EXPIRE ключей `ws:conn:{fd}` и `ws:user:{uid}`.
- Redis через `support\Redis` (плагин webman redis, см. существующее использование `app/queue/redis`).
- Идентификатор узла берётся из `ws.constructor.node_id` в `config/process.php` (по умолчанию `gethostname()`, можно изменить).

- [ ] **Шаг 1: Интерфейс PushProvider + NullPushProvider**

```php
interface PushProvider { public function send(int $uid, array $payload): void; }
class NullPushProvider implements PushProvider { public function send(int $uid, array $payload): void {} }
```

Фабрика в Deliverer: `push()` берёт реализацию из конфига или статической map (в M3 зафиксирован NullPushProvider; `ponytail: для интеграции вендора достаточно добавить класс реализации + ветку фабрики`).

- [ ] **Шаг 2: Deliverer (ядро доставки между узлами)**

Статические методы:
- `deliver(Message $msg, int $senderId): void`: взять `ConversationMember::where('conversation_id',$msg->conversation_id)->where('status',1)->pluck('user_id')`; для каждого участника:
  - `ConnectionRegistry::localFd($uid)` найден → в этом worker через `sendToFd` отправить `{type:'message', data:{...поля msg..., sender_id}}`;
  - не найден → `Redis::publish('im:user:'.$uid, json_encode([...]))` (другие узлы после подписки проверяют локальную Map и пушат напрямую); никто не подписан на канал → `Redis::rpush('im:offline:'.$uid, $payload)` + `LTRIM` cap 200.
  - После постановки в офлайн-очередь вызвать `PushProvider::send($uid, payload)` (в M3 Null — no-op).
  - Управление подписками узла: `bootstrap(int $workerFd)` использует `\Workerman\Timer` каждые 5s для дифференциальной подписки на каналы локально онлайн-пользователей `im:user:*` (колбэк `Redis::subscribe` пушит на локальный fd — см. пример подписки Redis в workerman). Колбэк подписки получил сообщение `im:user:{uid}` → если `localFd($uid)` найден, пушить напрямую, иначе игнорировать (отправитель уже записал офлайн-очередь).
