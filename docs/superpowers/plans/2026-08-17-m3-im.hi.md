**आर्किटेक्चर:** service (webman) एक ws worker (8789) जोड़ता है, कनेक्शन रजिस्ट्रेशन Redis में डबल-राइट करता है (`ws:conn:{fd}` TTL 60s + नोड इंडेक्स `ws:user:{uid}`) + worker की मेमोरी Map; चैनल प्रति-उपयोगकर्ता `im:user:{uid}` क्रॉस-नोड pub/sub हैं। सभी राइट पाथ WS से होकर जाते हैं (send/read/typing/recall), रीड पाथ REST से (कन्वर्सेशन/हिस्ट्री पेजिनेशन)। डिलीवरी: ऑनलाइन डायरेक्ट पुश + ऑफलाइन क्यू `im:offline:{uid}` (cap 200) + `PushProvider` इंटरफ़ेस (M3 में NullProvider, पोलिंग फॉलबैक)। मैसेज आइडेम्पोटेंसी: SETNX `im:dedup:{uid}:{client_msg_id}` TTL 24h + DB यूनिक इंडेक्स। **im proto की ज़रूरत नहीं** (कोई क्रॉस-सर्विस कॉल नहीं, gRPC केवल M2 की संपत्ति है)।

**टेक स्टैक:** PHP 8.3 / webman 2.x / workerman ws / Redis (webman/redis प्लगइन) / Eloquent / sqlite :memory: टेस्ट; Android OkHttp WebSocket + kotlinx.serialization; iOS URLSessionWebSocketTask; HarmonyOS @ohos.net.webSocket।

**पुष्टि किए गए निर्णय:** पुश रणनीति = NullProvider + इन-ऐप नोटिफिकेशन + पोलिंग फॉलबैक (उपयोगकर्ता द्वारा स्वीकृत); वॉइस/कॉल/मल्टी-डिवाइस मल्टी-कनेक्शन M4 तक स्थगित।

- [ ] **चरण 2: ConnectionRegistry (लोकल कनेक्शन टेबल + Redis रजिस्ट्रेशन)**

स्टैटिक क्लास। `Map<int fd, int uid>` (मेमोरी) + `Map<int uid, int fd>` सिंगल-कनेक्शन नीति। मेथड:
- `attach(int $fd, int $uid)`: यदि uid के पास पहले से पुराना fd है → किक-आउट के लिए पुराना fd लौटाएं (`kicked` फ्रेम पुश करें + close), फिर नया fd पंजीकृत करें; Redis में `ws:conn:{fd}` = uid (EXPIRE 60) और `ws:user:{uid}` = इस नोड की पहचान लिखें (node id `gethostname().':'.posix_getpid()` या config में `im.node_id` का उपयोग करें, लिखते समय EXPIRE 60)।
- `detach(int $fd)`: मेमोरी से हटाएं + Redis DEL `ws:conn:{fd}`; यदि `ws:user:{uid}` इस नोड की ओर इशारा करता है तो DEL करें।
- `localFd(int $uid): ?int`: मेमोरी खोज।
- `heartbeat(int $fd, int $uid)`: `ws:conn:{fd}` और `ws:user:{uid}` का EXPIRE नवीनीकृत करें।
- Redis `support\Redis` का उपयोग करें (webman redis प्लगइन, मौजूदा `app/queue/redis` उपयोग देखें)।
- नोड पहचान `config/process.php` के `ws.constructor.node_id` से ली जाती है (डिफ़ॉल्ट `gethostname()`, बदला जा सकता है)।

- [ ] **चरण 1: PushProvider इंटरफ़ेस + NullPushProvider**

```php

```

- [ ] **चरण 2: Deliverer (क्रॉस-नोड डिलीवरी कोर)**

स्टैटिक मेथड:
- `deliver(Message $msg, int $senderId): void`: `ConversationMember::where('conversation_id',$msg->conversation_id)->where('status',1)->pluck('user_id')` लें; प्रत्येक मेंबर के लिए:
  - `ConnectionRegistry::localFd($uid)` हिट → उस worker में `sendToFd` से `{type:'message', data:{...msg फ़ील्ड..., sender_id}}` पुश करें;
  - मिस → `Redis::publish('im:user:'.$uid, json_encode([...]))` (अन्य नोड सब्सक्राइब करके लोकल Map जांचने के बाद सीधे पुश करते हैं); चैनल पर कोई सब्सक्राइब नहीं → `Redis::rpush('im:offline:'.$uid, $payload)` + `LTRIM` cap 200।
  - ऑफलाइन एनक्यू के बाद `PushProvider::send($uid, payload)` कॉल करें (M3 में Null नो-ऑप)।
  - नोड सब्सक्रिप्शन प्रबंधन: `bootstrap(int $workerFd)` `\Workerman\Timer` का उपयोग करके हर 5s में `im:user:*` पर लोकल ऑनलाइन उपयोगकर्ताओं के चैनलों की डिफरेंशियल सब्सक्रिप्शन करता है (`Redis::subscribe` कॉलबैक का उपयोग करके लोकल fd पर पुश करें — workerman Redis सब्सक्रिप्शन उदाहरण देखें)। सब्सक्रिप्शन कॉलबैक `im:user:{uid}` मैसेज प्राप्त करता है → यदि `localFd($uid)` हिट हो तो सीधे पुश करें, अन्यथा अनदेखा करें (भेजने वाले ने पहले ही ऑफलाइन क्यू लिख दी है)।
- `notifyRead(int $cid, int $uid, int $lastReadId): void`: प्रत्येक मेंबर के चैनल पर publish करें `{type:'read', data:{conversation_id,user_id,last_read_id}}` (ऑनलाइन पुश, ऑफलाइन पर्सिस्टेंस नहीं — रीड सेमेंटिक्स DB पर आधारित, रीकनेक्ट पर फिर से लाया जाता है)।
- `relayTyping(int $cid, int $uid): void`: प्रत्येक मेंबर को publish करें `{type:'typing', data:{conversation_id,user_id}}`, केवल `!= $uid` वाले मेंबरों को पुश करें।
- `notifyRecall(int $cid, int $mid, int $uid): void`: publish करें `{type:'recall', data:{conversation_id,message_id,user_id}}`, ऑफलाइन मेंबर भी `im:offline:{uid}` में एनक्यू हों (रिकॉल नोटिफिकेशन को ऑफलाइन डिलीवरी चाहिए)।
