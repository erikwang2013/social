**الهدف:** تسليم M3 P1: حلقة مغلقة لرسائل النص/الصور في الدردشة الخاصة والجماعية — بوابة WS (webman ws worker + Redis pub/sub عبر العقد)، نموذج بيانات من أربع جداول، الكتابة عبر WS / القراءة عبر REST، دفع مباشر عبر الإنترنت + قائمة انتظار دون اتصال + تراجع بالاستقصاء، ودمج عملاء WS على المنصات الثلاث.

**البنية:** service (webman) يضيف ws worker (8789)، وتسجيل الاتصالات يكتب مرتين في Redis (`ws:conn:{fd}` TTL 60s + فهرس العقدة `ws:user:{uid}`) + Map في ذاكرة العامل؛ القنوات لكل مستخدم `im:user:{uid}` pub/sub عبر العقد. جميع مسارات الكتابة تمر عبر WS (send/read/typing/recall)، ومسارات القراءة عبر REST (المحادثات/ترقيم الصفحات للتاريخ). التسليم: دفع مباشر عبر الإنترنت + قائمة انتظار دون اتصال `im:offline:{uid}` (سقف 200) + واجهة `PushProvider` (في M3، NullProvider، التراجع بالاستقصاء). تكافؤ الرسائل: SETNX `im:dedup:{uid}:{client_msg_id}` TTL 24h + فهرس فريد في قاعدة البيانات. **لا حاجة لـ im proto** (لا استدعاءات بين الخدمات، gRPC مجرد أصل من M2).

**الحزمة التقنية:** PHP 8.3 / webman 2.x / workerman ws / Redis (إضافة webman/redis) / Eloquent / اختبارات sqlite :memory:؛ Android OkHttp WebSocket + kotlinx.serialization؛ iOS URLSessionWebSocketTask؛ HarmonyOS @ohos.net.webSocket.

**القرارات المؤكدة:** استراتيجية الدفع = NullProvider + إشعارات داخل التطبيق + تراجع بالاستقصاء (بموافقة المستخدم)؛ الصوت/المكالمات/الأجهزة المتعددة والاتصالات المتعددة مؤجلة إلى M4.

- [ ] **الخطوة 2: ConnectionRegistry (جدول الاتصالات المحلية + التسجيل في Redis)**

فئة ثابتة. `Map<int fd, int uid>` (ذاكرة) + `Map<int uid, int fd>` سياسة الاتصال الواحد. الطرق:
- `attach(int $fd, int $uid)`: إذا كان للـ uid fd قديم بالفعل → أعد fd القديم للطرد (دفع إطار `kicked` + close)، ثم سجل fd الجديد؛ اكتب في Redis `ws:conn:{fd}` = uid (EXPIRE 60) و`ws:user:{uid}` = معرّف هذه العقدة (node id عبر `gethostname().':'.posix_getpid()` أو `im.node_id` من الإعدادات، EXPIRE 60 عند الكتابة).
- `detach(int $fd)`: إزالة من الذاكرة + Redis DEL `ws:conn:{fd}`؛ إذا كان `ws:user:{uid}` يشير إلى هذه العقدة فـ DEL.
- `localFd(int $uid): ?int`: بحث في الذاكرة.
- `heartbeat(int $fd, int $uid)`: تجديد EXPIRE لكل من `ws:conn:{fd}` و`ws:user:{uid}`.
- Redis عبر `support\Redis` (إضافة webman redis، انظر الاستخدام الحالي لـ `app/queue/redis`).
- يُؤخذ معرّف العقدة من `ws.constructor.node_id` في `config/process.php` (افتراضيًا `gethostname()`، قابل للتغيير).

- [ ] **الخطوة 1: Envelope (تحليل/تسلسل الظرف)**

الإطار الوارد JSON `{type, seq, data}`؛ الإطار الصادر `{type, seq?, data}`. `Envelope::decode(string $raw): ?array` (فشل json/غياب type يعيد null)؛ `Envelope::encode(string $type, array $data, ?int $seq=null): string`. الثوابت: `T_SEND='send' T_ACK='ack' T_READ='read' T_TYPING='typing' T_RECALL='recall' T_PING='ping'`؛ `T_MESSAGE='message' T_KICKED='kicked' T_PONG='pong' T_ERROR='error'`.

- [ ] **الخطوة 2: ActionHandler::handle(int $fd, int $uid, array $env): void**

التوزيع حسب `$env['type']`، والأنواع غير المعروفة تعيد `{type:'error', data:{msg:'unknown type'}}`:
- `ping` → إعادة `pong` (صدى seq)؛ `ConnectionRegistry::heartbeat($fd,$uid)`.
- `send` → التحقق من `data.{conversation_id, client_msg_id}` وواحد على الأقل من `content|image_url` (الغياب → error)؛ التكافؤ: `Redis::set('im:dedup:'.$uid.':'.$cmid, '1', 'EX', 86400, 'NX')`، عند false → الاستعلام عن قاعدة البيانات وإعادة `{type:'ack', data:{client_msg_id, message_id}}` ثم return؛ الحفظ (`Message::create`، الفهرس الفريد في قاعدة البيانات كضمان — عند التعارض إعادة ack بالمعرّف الموجود) → `Deliverer::deliver($msg, $uid)` (المهمة 5) → إعادة `{type:'ack', data:{client_msg_id, message_id}}`.
- `read` → التحقق من conversation_id؛ `MessageRead::advance($cid,$uid,$data.last_read_id)`؛ `Deliverer::notifyRead($cid,$uid,$lastReadId)`.
- `typing` → `Deliverer::relayTyping($cid,$uid)` (ترحيل خالص دون حفظ).
- `recall` → التحقق من message_id وأن المرسل هو المستخدم نفسه؛ `Message::where('id',..)->where('sender_id',$uid)->first()`، رفض إذا كان `created_at` أقدم من >120s (error)؛ `update(['recall_status'=>1,'recall_at'=>now])`؛ `Deliverer::notifyRecall($cid,$mid,$uid)`.

- [ ] **الخطوة 2: Deliverer (نواة التسليم عبر العقد)**

- `deliver(Message $msg, int $senderId): void`: الحصول على `ConversationMember::where('conversation_id',$msg->conversation_id)->where('status',1)->pluck('user_id')`؛ لكل عضو:
  - `ConnectionRegistry::localFd($uid)` إصابة → في ذلك العامل الدفع عبر `sendToFd` بإطار `{type:'message', data:{...حقول msg..., sender_id}}`؛
  - عدم إصابة → `Redis::publish('im:user:'.$uid, json_encode([...]))` (العقد الأخرى بعد الاشتراك تتحقق من الخريطة المحلية وتدفع مباشرة)؛ لا أحد مشترك في القناة → `Redis::rpush('im:offline:'.$uid, $payload)` + `LTRIM` سقف 200.
  - بعد وضعها في قائمة دون اتصال استدعاء `PushProvider::send($uid, payload)` (في M3 Null بلا عملية).
  - إدارة اشتراكات العقدة: `bootstrap(int $workerFd)` يستخدم `\Workerman\Timer` كل 5 ثوانٍ للاشتراك التفاضلي في قنوات المستخدمين المحليين المتصلين على `im:user:*` (استخدام رد نداء `Redis::subscribe` الذي يدفع إلى fd المحلي — انظر مثال اشتراك Redis في workerman). يتلقى رد النداء رسالة `im:user:{uid}` → إذا كانت `localFd($uid)` إصابة فادفع مباشرة، وإلا فتجاهل (المرسل كتب قائمة الانتظار دون اتصال بالفعل).
- `notifyRead(int $cid, int $uid, int $lastReadId): void`: نشر في قنوات كل عضو `{type:'read', data:{conversation_id,user_id,last_read_id}}` (دفع عبر الإنترنت، دون حفظ خارج الاتصال — دلالات القراءة في قاعدة البيانات، تُجلب مجددًا عند إعادة الاتصال).
- `relayTyping(int $cid, int $uid): void`: نشر لكل عضو `{type:'typing', data:{conversation_id,user_id}}`، الدفع فقط للأعضاء `!= $uid`.
- `notifyRecall(int $cid, int $mid, int $uid): void`: نشر `{type:'recall', data:{conversation_id,message_id,user_id}}`، والأعضاء خارج الاتصال يُدرجون أيضًا في `im:offline:{uid}` (إشعارات الاسترجاع تحتاج تسليمًا دون اتصال).
