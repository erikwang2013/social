# Plan de mise en œuvre du jalon M3 IM (P1 : boucle fermée messages texte + image)

**语言 / Languages:** [中文](2026-08-17-m3-im.md) · [English](2026-08-17-m3-im.en.md) · [한국어](2026-08-17-m3-im.ko.md) · [Русский](2026-08-17-m3-im.ru.md) · [Deutsch](2026-08-17-m3-im.de.md) · [Français](2026-08-17-m3-im.fr.md) · [Español](2026-08-17-m3-im.es.md) · [Português](2026-08-17-m3-im.pt.md) · [हिन्दी](2026-08-17-m3-im.hi.md) · [العربية](2026-08-17-m3-im.ar.md) · [বাংলা](2026-08-17-m3-im.bn.md) · [Bahasa Indonesia](2026-08-17-m3-im.id.md) · [日本語](2026-08-17-m3-im.ja.md)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objectif :** Livrer M3 P1 : boucle fermée des messages texte/image en messagerie privée et de groupe — passerelle WS (webman ws worker + Redis pub/sub inter-nœuds), modèle de données à quatre tables, écriture via WS / lecture via REST, push direct en ligne + file hors ligne + repli par polling, intégration des clients WS sur les trois plateformes.

**Architecture :** service (webman) ajoute un ws worker (8789), l'enregistrement des connexions écrit en double dans Redis (`ws:conn:{fd}` TTL 60s + index de nœud `ws:user:{uid}`) + Map en mémoire du worker ; les canaux sont par utilisateur `im:user:{uid}` en pub/sub inter-nœuds. Tous les chemins d'écriture passent par WS (send/read/typing/recall), les chemins de lecture par REST (conversations/pagination de l'historique). Distribution : push direct en ligne + file hors ligne `im:offline:{uid}` (cap 200) + interface `PushProvider` (en M3, NullProvider, repli par polling). Idempotence des messages : SETNX `im:dedup:{uid}:{client_msg_id}` TTL 24h + index unique en base. **Pas besoin d'im proto** (aucun appel inter-services, gRPC n'est qu'un actif de M2).

**Pile technique :** PHP 8.3 / webman 2.x / workerman ws / Redis (plugin webman/redis) / Eloquent / tests sqlite :memory: ; Android OkHttp WebSocket + kotlinx.serialization ; iOS URLSessionWebSocketTask ; HarmonyOS @ohos.net.webSocket.

**Décisions confirmées :** Stratégie de push = NullProvider + notifications in-app + repli par polling (validé par l'utilisateur) ; voix/appels/multi-appareils multi-connexions reportés à M4.

- [ ] **Étape 1 : Interface PushProvider + NullPushProvider**

```php
interface PushProvider { public function send(int $uid, array $payload): void; }
class NullPushProvider implements PushProvider { public function send(int $uid, array $payload): void {} }
```

Fabrique dans Deliverer : `push()` prend l'implémentation depuis la config ou une map statique (M3 fixe NullPushProvider ; `ponytail: l'intégration d'un fournisseur ne nécessite qu'une classe d'implémentation + une branche de fabrique`).

- [ ] **Étape 2 : Deliverer (cœur de distribution inter-nœuds)**

Méthodes statiques :
- `deliver(Message $msg, int $senderId): void` : récupérer `ConversationMember::where('conversation_id',$msg->conversation_id)->where('status',1)->pluck('user_id')` ; pour chaque membre :
  - `ConnectionRegistry::localFd($uid)` trouvé → dans ce worker pousser `{type:'message', data:{...champs msg..., sender_id}}` via `sendToFd` ;
  - non trouvé → `Redis::publish('im:user:'.$uid, json_encode([...]))` (les autres nœuds poussent directement après abonnement et vérification de la Map locale) ; personne n'est abonné au canal → `Redis::rpush('im:offline:'.$uid, $payload)` + `LTRIM` cap 200.
  - Après mise en file hors ligne, appeler `PushProvider::send($uid, payload)` (en M3, Null sans opération).
  - Gestion des abonnements du nœud : `bootstrap(int $workerFd)` utilise `\Workerman\Timer` toutes les 5s pour abonner en différentiel les canaux des utilisateurs locaux en ligne sur `im:user:*` (utiliser le callback `Redis::subscribe` poussant vers le fd local — voir l'exemple d'abonnement Redis de workerman). Le callback d'abonnement reçoit le message `im:user:{uid}` → si `localFd($uid)` trouvé, pousser directement, sinon ignorer (l'expéditeur a déjà écrit la file hors ligne).
- `notifyRead(int $cid, int $uid, int $lastReadId): void` : publier sur les canaux de chaque membre `{type:'read', data:{conversation_id,user_id,last_read_id}}` (push en ligne, sans persistance hors ligne — la sémantique de lecture repose sur la base, re-récupérée à la reconnexion).
- `relayTyping(int $cid, int $uid): void` : publier à chaque membre `{type:'typing', data:{conversation_id,user_id}}`, ne pousser qu'aux membres `!= $uid`.
- `notifyRecall(int $cid, int $mid, int $uid): void` : publier `{type:'recall', data:{conversation_id,message_id,user_id}}`, les membres hors ligne sont aussi mis en file `im:offline:{uid}` (les notifications de rappel nécessitent une distribution hors ligne).
