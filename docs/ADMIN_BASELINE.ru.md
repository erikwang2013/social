Базовое состояние и точки входа для доработки open-admin (webman v2 + административная панель Flutter).

## Текущая версия и состояние запуска

| Пункт | Значение |
|---|---|
| Фреймворк | webman v2 (workerman/webman-framework **v2.2.3**) |
| PHP | 8.3.7 (CLI) |
| Зависимости | `composer install` успешно, 69 пакетов |
| .env | **Отсутствует** (в репозитории нет `.env` и `.env.example`; нужно создать локально под MySQL/Redis) |
| Точка входа миграций | Нет (`think`/`artisan` отсутствуют; в webman нет встроенных миграций, в M0 задач миграции нет) |
| Тесты | `vendor/bin/phpunit`: 60 tests / 136 assertions, **4 errors / 7 failures / 6 warnings / 1 risky — не полностью зелёные** |

## Включённые модули (подтверждено в README)

- **JWT-аутентификация**: вход/обновление/выход, капча по клику, блокировка аккаунта (5 неудачных попыток — блокировка на 15 минут), ограничение параллельных сессий (≤3 токена на пользователя)
- **RBAC**: дерево ролей/прав, авторизация с точностью method.path
- **Аудит операций**: запрос логов + определение 8 платформенных источников
- **Управление файлами**: загрузка / экспорт Excel / экспорт PDF (с маскированием)
- **i18n**: переключение китайского/английского (Accept-Language / ?lang=)
- Прочее: дашборд (кэш Redis), конфигурация системы, health check/metrics/OpenAPI 3.0, 18-уровневая защита

## Детали сбоев тестов (все — существующие пробелы проекта, не внесены этим изменением)

| Группа тестов | Сбой | Причина |
|---|---|---|
| `EnvConfigTest` (5) | 4 failure + 1 error | Тесты утверждают, что `.env`/`.env.example` обязаны существовать и значения getenv для `APP_NAME`/`JWT_SECRET_KEY`/`DB_HOST` и др. должны быть заданы; в репозитории нет примера env |
| `CaptchaTest` (4) | 3 error + 1 failure (ещё 1 risky без утверждений) | Капча по клику зависит от хранилища Redis, локально не предоставлено |
| `BackendEnhancementTest` (2) | 2 failure | Утверждается, что источник данных `user` содержит searchable, а middleware — cors/rate_limit; расхождение конфигурации и утверждений тестов |

Локальные шаги для восстановления зелёного статуса: создать `.env` по ключам конфигурации в `config/` (добавить ключи, от которых зависит EnvConfigTest), предоставить MySQL + Redis (для CaptchaTest), а затем ответственный выносит решение по двум расхождениям конфигурации в BackendEnhancementTest.

## Готовность gRPC (T3)

- Пакеты Composer установлены: `grpc/grpc 1.82.0`, `google/protobuf 5.35` (`--no-plugins` обходит баг повторной загрузки плагина security-php)
- Заглушки PHP сгенерированы: `admin/generated/` (`Social/Admin/V1/AdminServiceClient.php` и др., включая три набора контрактов: infra/user)
- **Расширение grpc PHP не установлено**: у pecl нет прав на запись и для sudo нужен пароль; для запуска gRPC-клиента требуется `sudo pecl install grpc`

## Точки входа доработки (восемь новых пунктов §3.4 документа проектирования)

1. Рабочее место модерации контента: двуязычное сопоставление постов/комментариев/изображений, многоязычные шаблоны причин отклонения, наказания пользователей
2. Очередь обработки жалоб
3. Стол запросов GDPR (тикеты на экспорт/удаление)
4. Интеграция дашборда данных с bee_tsdb
5. Управление терминами i18n (общий CRUD для четырёх клиентов)
6. Управление библиотекой подарков (SKU, цена, эффекты, многоязычные названия)
7. Конфигурация провайдеров трансляций (стратегия маршрутизации, порядок переключения)
8. Проверка заявок на вывод средств

**Точки интеграции gRPC**: заглушки контрактов на стороне admin — в `admin/generated/` (повторное использование `Social/Admin/V1` для пробы доступности + последующие бизнес-сообщения); вызовы к service идут через `Social\User\V1\UserServiceClient`, к infrastructure — через `Social\Infra\V1\InfraServiceClient`; цепочка проверки доступности с service/infrastructure описана в `service/README.grpcs.md` и T10-интеграционных проверках.
