## Проблемы окружения, исправленные/обработанные в этом раунде (не изменения бизнес-кода продукта)

1. **Сломан переопределение пустого пароля БД в run.php (дефект тест-скрипта, исправлено)**: константа `DB` использует `getenv('DB_PASS') ?: 'root'`; при пустой строке переменной окружения `?:` считает её ложью и откатывается на 'root', поэтому локальное подключение root с пустым паролем отклоняется (`Access denied ... using password: YES`). Заменено на `getenv('DB_PASS') ?? 'root'` (дефолт только при отсутствии), изменение в одну строку (tests/api/run.php:26).
2. **Порт 8788 service занят чужим процессом (окружение, обработано)**: процесс service другого проекта на этой машине — `property-management-platform` (master 2004768, стартовал 08:07) — слушал 8788, а его `.env` указывает на БД `property_management`; фактически social service не работал, из-за чего маршруты IM/голоса с S45 отдавали 404, а SQL фазы очистки бил не в ту БД. Процесс остановлен, social service перезапущен на 8788/8789 (`DB_HOST=127.0.0.1 DB_PORT=3306 DB_USERNAME=root DB_PASSWORD=''`), health-проверка вернула `social-service`.
3. **Апгрейд ImageMagick 7 сломал драйвер Imagick капчи (окружение, обработано)**: после обновления системного ImageMagick до 7.1.2-27 (сборка 2026-07-08) удалён `PixelsResource`, imagick 3.8.1 больше не определяет `Imagick::RESOURCETYPE_PIXELS`, и конструктор `ImagickDriver` из poster-php сразу бросает `Undefined constant` (vendor-код, не менялся), поэтому генерация/проверка капчи (A05/A06) дают 500 и каскадно блокируют вход A08-A11. **Обработка**: admin перезапущен с переключателем драйвера, предусмотренным в документации конфигурации — `POSTER_IMAGE_DRIVER=gd` (admin/config/poster.php:17 нативно поддерживает gd/imagick/auto); после перевода капчи на GD вся цепочка работает. Для возврата драйвера Imagick нужно понизить ImageMagick до 6.x или обновить poster-php для совместимости с IM7.
4. **Пароль root в MySQL изменён на пустой**: в прошлом раунде фиксировался `root/root`, в этом раунде вход работает с пустым паролем; все сервисы и скрипты запущены с пустым паролем.
5. **Окружение перезапуска admin**: по-прежнему действует «у admin нет .env, зависит от переменных окружения» из прошлого раунда; команды перезапуска — ниже в «Окружение и воспроизведение».
6. **service/.env всё ещё `service/.env.api-test-bak`**: вынесен в прошлом раунде для проверки связности и не восстановлен (восстановление ограничено политикой доступа к .env); в этом раунде сервис снова запущен через переменные окружения. Нужен ручной `mv service/.env.api-test-bak service/.env` (после восстановления перезапустить сервис, обращая внимание на адрес БД, на который он указывает).
7. **Elasticsearch не запущен**: `GET /api/v1/search/posts` возвращает 503 (предусмотренная деградация); поисковые тесты группы S обработаны как ожидалось (принимается 0 или 503), не засчитаны как падения.

## Несоответствия контракту/документации (рекомендуется исправить, не блокирует)

- Документация капчи (apidoc и комментарии CaptchaController) описывает `clicks=[{x,y}]` как массив объектов, а реализация `poster-php` требует массив пар координат `[[x,y]]`; передача объектов по документации всегда приводит к сбою.
- Голосовая загрузка возвращает `voice_url` как `/voice/{md5}.m4a` (относительно корня API, без префикса `/api/v1`); клиенту нужно самому добавлять `/api/v1` для доступа; доступ к файлам идёт через аутентифицированные маршруты (требуется token).

## Окружение и воспроизведение

- Тестовые учётные данные: тестовый аккаунт `e2e_smoke` (admin, пароль только для тестов) + `apitest_*@test.dev` (service, автоочистка после прогона), все записаны в константы `tests/api/run.php`; реальные ключи не использовались.
- Воспроизведение:

```bash
cd /home/wwwroot/social/admin && DB_PASSWORD='' ENCRYPTABLE_KEY='apitest-enc-16b!!' \
  ENCRYPTION_KEY='apitest-db-encrypt-key-32-byte!!' POSTER_IMAGE_DRIVER=gd \
  php start.php start                                          # admin :8791
cd /home/wwwroot/social/service && DB_HOST=127.0.0.1 DB_PORT=3306 DB_USERNAME=root \
  DB_PASSWORD='' php start.php start                           # service :8788
cd /home/wwwroot/social/tests/api && DB_PASS='' php run.php    # повторный прогон (116 тестов)
```

- Внимание: порт 8788 не должен быть занят service `property-management-platform` (у обоих проектов одинаковые порты по умолчанию; при наличии обоих проектов на одной машине их нужно разнести).
