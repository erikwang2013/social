## Область тестирования и список страниц

Оба бэкенда webman запущены как реальные процессы: `admin` (:8791), `service` (:8788, WS :8789).
В `app/view/` обеих сторон только шаблоны по умолчанию (`index/view.html`), традиционных многопage-шаблонов нет — фактически «страницами» являются API-эндпоинты,
а веб-фронтенды реализованы клиентами Flutter/HarmonyOS (в `apps/` нет запускаемого веб-UI, поэтому они вне области E2E).

## Способ запуска

```bash
cd tests/e2e && npx playwright test          # все
# или по файлам: admin-pages.spec.js / admin-auth.spec.js / service-journey.spec.js
```

- Фикстура тестового аккаунта: `e2e_smoke`, пароль `ApiTest!2026` (предзаполнено через SQL, см. `tests/api/run.php`)
- Слайдер-капча решается через попиксельную корреляцию Пирсона между «фрагментом пазла и фоновым изображением» (реальный путь взаимодействия, без обхода);
  тип капчи случаен (click/rotate/slider), автоматически решается только slider, поэтому скрипт повторяет попытки со сменой изображения до попадания.

## Блокировки / ограничения окружения

1. **Поиск постов 503**: `/api/v1/search/posts` зависит от Elasticsearch (Scout), в данном окружении ES не запущен → возвращает 503.
   Тест проходит с пометкой `blocked`; после запуска ES необходимо проверить попадания.
2. **Главная `/` service требует явный маршрут**: маршрутизация по умолчанию webman-framework v2.2.4 больше не резолвит `/` на
   `IndexController@index` (когда-то вызывала 404 на корневом пути, из-за чего падал кейс главной). Исправлено явной регистрацией
   `Route::get('/', ...)` в `service/config/route.php`; действует после перезапуска service.
3. **Совместимость Imagick для капчи admin**: в сборке Imagick этой машины нет константы `Imagick::RESOURCETYPE_PIXELS`,
   поэтому драйвер `auto` ошибочно выбрал бы ImagickDriver и вызвал generate 500 (`admin/config/poster.php` теперь откатывается на gd
   в зависимости от наличия константы; требуется перезапуск admin).
4. **Память GD для капчи admin**: `GdDriver` декодирует большие изображения (фон 5472x3648) при `memory_limit 128M`,
   при последовательных generate существует риск OOM (в длительных прогонах admin однажды падал). Обход: перезапуск admin перед капчей,
   и запуск пакетами (admin-pages / admin-auth / service раздельно). Ограничение окружения, а не дефект бизнес-кода.
5. **Случайный тип капчи**: generate выбирает один из трёх; click/rotate не предоставляют решаемых данных, автоматически проходится только slider (макс. 12 попыток).
6. **Пустой пароль root в БД**: локальное тестовое окружение предоставляет MySQL с root/пустым паролем, `.env` обеих приложений по умолчанию согласованы.
7. **Мобильные apps/**: android/harmonyos/ios не имеют запускаемого веб-UI и не включены в браузерное E2E.

## Заключение

Вход admin (включая слайдер-капчу) и 22 административных эндпоинта, а также все 19 полных пользовательских сценариев service проходят
(этот прогон добавил 6 кейсов: пакетная активация admin/экспорт Excel/валидация смены пароля, service 401 без входа/отписка/одно уведомление отмечено прочитанным).
Исправлено 2 реальных дефекта: 404 корневого пути service (добавлен явный маршрут), generate 500 капчи admin
(отсутствует константа Imagick → откат на GD, уже в конфиге, действует после перезапуска).
Единственная блокировка — сервис поиска (ES) не развёрнут; остальные цепочки (регистрация/вход/посты/взаимодействия/уведомления/IM/голос) проверены и работают.
