## परीक्षण क्षेत्र और पृष्ठ सूची

दोनों webman बैकएंड वास्तविक प्रक्रियाओं के रूप में चलते हैं: `admin` (:8791), `service` (:8788, WS :8789)।
दोनों ओर की `app/view/` में केवल डिफ़ॉल्ट टेम्पलेट (`index/view.html`) हैं, कोई पारंपरिक बहु-पृष्ठ टेम्पलेट नहीं — वास्तविक "पृष्ठ" API एंडपॉइंट हैं,
और वेब फ्रंटएंड Flutter/HarmonyOS क्लाइंट द्वारा संभाले जाते हैं (`apps/` में कोई चलने योग्य वेब UI नहीं है, E2E दायरे में नहीं)।

## चलाने का तरीका

```bash
cd tests/e2e && npx playwright test          # सभी
# या फ़ाइल के अनुसार: admin-pages.spec.js / admin-auth.spec.js / service-journey.spec.js
```

- परीक्षण खाता फिक्स्चर: `e2e_smoke`, पासवर्ड `ApiTest!2026` (SQL से पूर्व-जोड़ा गया, देखें `tests/api/run.php`)
- स्लाइडर कैप्चा "पहेली टुकड़ा बनाम पृष्ठभूमि छवि" के पिक्सेल Pearson सहसंबंध से हल होता है (वास्तविक इंटरैक्शन पथ, कोई बाईपास नहीं);
  कैप्चा प्रकार यादृच्छिक है (click/rotate/slider), केवल slider स्वतः हल हो सकता है, इसलिए स्क्रिप्ट सफल होने तक नई छवि के साथ पुनः प्रयास करती है।

## ब्लॉकर / वातावरण सीमाएँ

1. **पोस्ट खोज 503**: `/api/v1/search/posts` Elasticsearch (Scout) पर निर्भर है, इस वातावरण में ES प्रारंभ नहीं है → 503 लौटाता है।
   केस `blocked` चिह्नित कर पास होता है; हिट सत्यापित करने के लिए ES प्रारंभ करना आवश्यक है।
2. **service होमपेज `/` को स्पष्ट रूट चाहिए**: webman-framework v2.2.4 का डिफ़ॉल्ट रूटिंग अब `/` को
   `IndexController@index` पर हल नहीं करता (एक बार रूट पथ पर 404 हुआ, जिससे होमपेज केस विफल हुआ)। `service/config/route.php` में स्पष्ट रूप से
   `Route::get('/', ...)` पंजीकृत करके ठीक किया गया; service पुनः प्रारंभ करने पर प्रभावी।
3. **admin कैप्चा Imagick संगतता**: इस मशीन के Imagick बिल्ड में `Imagick::RESOURCETYPE_PIXELS` स्थिरांक नहीं है,
   इसलिए `auto` ड्राइवर गलती से ImagickDriver चुनकर generate 500 उत्पन्न करता (`admin/config/poster.php` अब स्थिरांक की उपस्थिति के अनुसार
   gd पर फ़ॉलबैक करता है; admin पुनः प्रारंभ करना आवश्यक)।
4. **admin कैप्चा GD मेमोरी**: `GdDriver` बड़ी छवियाँ (पृष्ठभूमि 5472x3648) डिकोड करता है और `memory_limit 128M` के साथ,
   लगातार generate से OOM जोखिम है (लंबे सूट में admin एक बार क्रैश हुआ)। उपाय: कैप्चा केस चलाने से पहले admin पुनः प्रारंभ करें,
   और बैचों में चलाएँ (admin-pages / admin-auth / service अलग-अलग)। यह वातावरण सीमा है, व्यावसायिक कोड दोष नहीं।
5. **कैप्चा प्रकार यादृच्छिक**: generate तीन में से एक चुनता है; click/rotate कोई हल योग्य डेटा नहीं देते, केवल slider स्वतः पास होता है (अधिकतम 12 प्रयास)।
6. **डेटाबेस root खाली पासवर्ड**: स्थानीय परीक्षण वातावरण MySQL को root/खाली पासवर्ड के साथ देता है, दोनों ऐप के `.env` डिफ़ॉल्ट संगत हैं।
7. **apps/ मोबाइल**: android/harmonyos/ios में कोई चलने योग्य वेब UI नहीं है, ब्राउज़र E2E में शामिल नहीं।

## निष्कर्ष

admin लॉगिन (स्लाइडर कैप्चा सहित) और 22 प्रशासनिक एंडपॉइंट, साथ ही service उपयोगकर्ता पक्ष के सभी 19 पूर्ण-प्रवाह केस पास होते हैं
(इस रन में 6 केस जोड़े गए: admin बैच सक्रियण/Excel निर्यात/पासवर्ड बदलाव सत्यापन, service बिना लॉगिन 401/अनफॉलो/एक नोटिफिकेशन पढ़ा हुआ चिह्नित)।
2 वास्तविक दोष ठीक किए गए: service रूट पथ 404 (स्पष्ट रूट जोड़ा गया), admin कैप्चा generate 500
(Imagick स्थिरांक गायब → GD पर फ़ॉलबैक, कॉन्फ़िग में शामिल, पुनः प्रारंभ करने पर प्रभावी)।
एकमात्र ब्लॉकर खोज सेवा (ES) की तैनाती का अभाव है; बाकी सभी श्रृंखलाएँ (रजिस्टर/लॉगिन/पोस्ट/इंटरैक्शन/नोटिफिकेशन/IM/वॉयस) कार्यशील सत्यापित हैं।
