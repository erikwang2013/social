## টেস্টের পরিধি ও পৃষ্ঠার তালিকা

দুটি webman ব্যাকএন্ডই বাস্তব প্রসেস হিসেবে চলে: `admin` (:8791), `service` (:8788, WS :8789)।
দুই পাশের `app/view/`-এ কেবল ডিফল্ট টেমপ্লেট (`index/view.html`) আছে, কোনো ঐতিহ্যবাহী মাল্টি-পেজ টেমপ্লেট নেই — প্রকৃত "পৃষ্ঠা" হলো API এন্ডপয়েন্ট,
আর ওয়েব ফ্রন্টএন্ড বহন করে Flutter/HarmonyOS ক্লায়েন্ট (`apps/`-এ কোনো চালানোর উপযোগী ওয়েব UI নেই, E2E পরিধির বাইরে)।

## চালানোর পদ্ধতি

```bash
cd tests/e2e && npx playwright test          # সবগুলো
# বা ফাইল অনুযায়ী: admin-pages.spec.js / admin-auth.spec.js / service-journey.spec.js
```

- টেস্ট অ্যাকাউন্ট ফিক্সচার: `e2e_smoke`, পাসওয়ার্ড `ApiTest!2026` (SQL দিয়ে আগেই বসানো, দেখুন `tests/api/run.php`)
- স্লাইডার ক্যাপচা "পাজল টুকরো বনাম ব্যাকগ্রাউন্ড ছবি"র পিক্সেল Pearson সম্পর্ক দিয়ে সমাধান হয় (বাস্তব ইন্টারঅ্যাকশন পথ, কোনো বাইপাস নেই);
  ক্যাপচা ধরন এলোমেলো (click/rotate/slider), শুধু slider-ই স্বয়ংক্রিয়ভাবে সমাধানযোগ্য, তাই স্ক্রিপ্ট সফল না হওয়া পর্যন্ত নতুন ছবি দিয়ে পুনরায় চেষ্টা করে।

## ব্লকার / পরিবেশের সীমাবদ্ধতা

1. **পোস্ট খোঁজা 503**: `/api/v1/search/posts` Elasticsearch (Scout)-এর উপর নির্ভরশীল, এই পরিবেশে ES চালু নেই → 503 ফেরত দেয়।
   কেসটি `blocked` চিহ্নিত হয়ে পাস করে; হিট যাচাই করতে ES চালু করা দরকার।
2. **service হোমপেজ `/`-এর জন্য স্পষ্ট রুট প্রয়োজন**: webman-framework v2.2.4-এর ডিফল্ট রাউটিং আর `/`-কে
   `IndexController@index`-এ সমাধান করে না (একবার রুট পাথে 404 ঘটিয়ে হোমপেজ কেস ব্যর্থ করেছিল)। `service/config/route.php`-এ স্পষ্টভাবে
   `Route::get('/', ...)` নিবন্ধন করে ঠিক করা হয়েছে; service পুনরায় চালু করলে কার্যকর হয়।
3. **admin ক্যাপচা Imagick সামঞ্জস্য**: এই মেশিনের Imagick বিল্ডে `Imagick::RESOURCETYPE_PIXELS` কনস্ট্যান্ট নেই,
   তাই `auto` ড্রাইভার ভুলভাবে ImagickDriver বেছে নিয়ে generate 500 ঘটাত (`admin/config/poster.php` এখন কনস্ট্যান্ট থাকা-না-থাকা অনুযায়ী
   gd-তে ফলব্যাক করে; admin পুনরায় চালু করতে হবে)।
4. **admin ক্যাপচা GD মেমোরি**: `GdDriver` বড় ছবি (ব্যাকগ্রাউন্ড 5472x3648) ডিকোড করে এবং `memory_limit 128M`-এর সাথে,
   ধারাবাহিক generate-এ OOM ঝুঁকি থাকে (দীর্ঘ স্যুটে admin একবার ক্র্যাশ করেছিল)। পরিহার: ক্যাপচা কেস চালানোর আগে admin পুনরায় চালু করুন,
   এবং ব্যাচে আলাদা করে চালান (admin-pages / admin-auth / service আলাদা)। এটি পরিবেশগত সীমাবদ্ধতা, ব্যবসায়িক কোডের ত্রুটি নয়।
5. **ক্যাপচা ধরন এলোমেলো**: generate তিনটির মধ্যে একটি বেছে নেয়; click/rotate কোনো সমাধানযোগ্য ডেটা দেয় না, শুধু slider স্বয়ংক্রিয়ভাবে পাস করে (সর্বোচ্চ 12 চেষ্টা)।
6. **ডেটাবেস root খালি পাসওয়ার্ড**: লোকাল টেস্ট পরিবেশ MySQL-কে root/খালি পাসওয়ার্ডে দেয়, দুই অ্যাপের `.env` ডিফল্ট সামঞ্জস্যপূর্ণ।
7. **apps/ মোবাইল**: android/harmonyos/ios-এ চালানোর উপযোগী ওয়েব UI নেই, ব্রাউজার E2E-তে অন্তর্ভুক্ত নয়।

## উপসংহার

admin লগইন (স্লাইডার ক্যাপচাসহ) এবং ২২টি অ্যাডমিন এন্ডপয়েন্ট, সাথে service ব্যবহারকারী পক্ষের ১৯টি পূর্ণ-প্রবাহ কেস সব পাস করে
(এই রানে ৬টি কেস যোগ হয়েছে: admin ব্যাচ সক্রিয়করণ/Excel এক্সপোর্ট/পাসওয়ার্ড পরিবর্তন যাচাই, service লগইন ছাড়া 401/আনফলো/একটি নোটিফিকেশন পঠিত চিহ্নিত)।
২টি প্রকৃত ত্রুটি ঠিক করা হয়েছে: service রুট পাথ 404 (স্পষ্ট রুট যোগ করা হয়েছে), admin ক্যাপচা generate 500
(Imagick কনস্ট্যান্ট নেই → GD-তে ফলব্যাক, কনফিগে আছে, পুনরায় চালু করলে কার্যকর)।
একমাত্র ব্লকার হলো সার্চ সার্ভিস (ES) মোতায়েন না থাকা; বাকি সব শৃঙ্খল (রেজিস্টার/লগইন/পোস্ট/ইন্টারঅ্যাকশন/নোটিফিকেশন/IM/ভয়েস) কার্যকর বলে যাচাই হয়েছে।
