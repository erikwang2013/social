## Список проблем

### 1. 🔴 Недействительный элемент конфигурации в корневом Cargo.toml

**Файл**: `Cargo.toml:24`  
**Проблема**: `name = "bee-rust"` в `[workspace.package]` — недействительный ключ, при каждой компиляции возникает предупреждение:

```
warning: /home/wwwroot/bee-rust/Cargo.toml: unused manifest key: workspace.package.name
```

**Исправление**: удалить строку `name = "bee-rust"`. Пакету уровня workspace не нужен name; он требуется только в `[package]` каждого под-crate.

---

### 2. 🔴 Отсутствует файл LICENSE

**Проблема**: корневой `Cargo.toml` объявляет `license = "Apache-2.0"`, но в корне репозитория нет файла `LICENSE`. Условия лицензии Apache-2.0 требуют включать копию лицензии в дистрибутивы.

**Исправление**: создать в корневом каталоге файл `LICENSE` с полным текстом лицензии Apache-2.0.

---

Crate с корректно объявленной лицензией: bee_router, bee_config, bee_session, bee_orm, bee_orm_macro

### 4. 🟡 Отсутствуют метаданные публикации на crates.io

Во всех crate отсутствуют следующие поля, что снижает обнаруживаемость на crates.io:

- `description` — краткое описание
- `repository` — ссылка на репозиторий
- `keywords` — поисковые ключевые слова
- `categories` — категории (например, `["web-programming", "database"]`)

Рекомендуется добавить общие поля в `[workspace.package]`:

```toml
[workspace.package]
repository = "https://github.com/erikwang2013/bee-rust"
keywords = ["web", "framework", "beego", "mvc"]
categories = ["web-programming"]
```

### 6. 🟡 Feature движков хранения — пустые заглушки

Следующие feature объявлены, но не имеют фактической реализации, являясь лишь пустыми заполнителями:

- `bee_search`: `elasticsearch`, `opensearch`, `clickhouse` — все `[]`
- `bee_graph`: `neo4j`, `nebulagraph`, `arangodb` — все `[]`
- `bee_tsdb`: `influxdb`, `iotdb`, `questdb` — все `[]`

Это означает, что примеры кода для поисковых движков, графовых БД и БД временных рядов из README не могут реально работать (их тесты также используют заглушки).

**Рекомендация**: пометить эти функции как «planned / в планах» в README либо добавить реальные зависимости драйверов и реализации.

---

### 7. 🟡 StubKvStore::expire() — пустая операция

**Файл**: `crates/bee_kv/src/lib.rs:111`  
**Проблема**: метод `expire()` тестовой заглушки `StubKvStore` не реализует логику истечения TTL, хотя trait определяет этот интерфейс. Значит, тесты не могут покрыть поведение, связанное с TTL.

---

### 8. 🟢 Избыточная аннотация cfg у RedisStore

**Файл**: `crates/bee_kv/src/redis_store.rs`  
**Проблема**: весь модуль уже условно компилируется через `#[cfg(feature = "redis")]` в `lib.rs`, поэтому аннотация `#[cfg(feature = "redis")]` внутри `redis_store.rs` избыточна (функционально верно, но не лаконично).

---

### 9. 🟢 Отсутствуют doc-тесты

Кроме `bee_template`, где есть 1 doc-тест, все остальные crate не имеют документационных тестов. Рекомендуется добавить примеры doc-тестов для ключевых trait (`Cache`, `KvStore`, `Controller` и др.).

---

### 10. 🟢 Файл bee_graph/src/lib.rs великоват

406 строк — близко к пределу 500 строк. Рекомендуется последующее разделение (например, на отдельные model.rs, query.rs).

## Проверка безопасности

- ✅ **Обнаружение атак**: SecurityFilter покрывает 27 типов атак, включая XSS, SQL-инъекции, инъекции команд и обход пути
- ✅ **Тесты безопасности**: 6 тестов безопасности покрывают основные типы атак
- ✅ **Ноль unsafe**: Во всём бизнес-коде нет блоков unsafe
- ✅ **Безопасность зависимостей**: в качестве движка обнаружения используется crate `security-rust`
- ⚠️ **QuerySet::to_sql()**: в коде уже есть комментарий о том, что метод только для отладки/тестирования; в продакшене необходимо использовать параметризованные запросы

## Резюме

Общее качество кода проекта хорошее: компиляция проходит, тесты полностью зелёные, Clippy без предупреждений, ноль unsafe-кода. Архитектура ясная, абстракции trait разумны. Основные проблемы сосредоточены в **полноте экосистемной конфигурации** — отсутствуют файл лицензии, неполные метаданные Cargo.toml, нет CI/CD и конфигурации форматирования. Эти проблемы не влияют на функциональность, но сказываются на профессионализме open-source проекта и опыте публикации на crates.io. Рекомендуется в первую очередь исправить пункты P0 и P1.
