## 수정된 문제

### BUG-001: bee_logs — `WorkerGuard`가 즉시 드롭되어 비동기 로그 유실

**심각도:** 높음  
**파일:** `crates/bee_logs/src/lib.rs:54,62`

`tracing_appender::non_blocking()`이 반환한 `WorkerGuard`가 `match` 분기 종료 시 drop되어
비동기 쓰기 워커 스레드가 즉시 중단되고 모든 비동기 로그 메시지가 유실됩니다.

**수정:** `Option<WorkerGuard>`를 보유하는 `LogHandle` 구조체를 추가하고, `Logger::init()`이
`Result<LogHandle, ...>`을 반환하도록 변경. 호출자는 지속적인 쓰기를 위해 `LogHandle`을 유지해야 합니다.

### BUG-002: bee_cache — TTL 만료 항목 메모리 누수

**심각도:** 중간  
**파일:** `crates/bee_cache/src/lib.rs:60-71`

`MemoryCache::get()`은 TTL 만료 감지 시 `None`만 반환하고 HashMap에서 항목을 삭제하지 않습니다.
장기 실행 애플리케이션에서 만료 항목이 계속 누적되어 메모리 누수가 발생합니다.

**수정:** `get()`이 만료 감지 후 읽기 잠금을 해제하고 쓰기 잠금을 획득한 뒤 만료 항목을 삭제합니다.

### BUG-003: examples/hello — 사용하지 않는 import 경고

**심각도:** 낮음  
**파일:** `examples/hello/src/main.rs:1`

`use bee_rust::prelude::*`가 사용되지 않아 컴파일 경고가 발생합니다.

**수정:** 해당 import를 제거하고, `init()` 반환값을 `_log_handle`에 바인딩하여 LogHandle이 조기에 drop되지 않도록 했습니다.

## 아키텍처 관찰

### 장점

1. **Crate 분리가 명확** — 15개 crate의 책임이 명확하고 의존 방향이 합리적 (기반 → 저장 → Web → 집계)
2. **Trait 추상화가 완전** — `KvStore`, `SearchEngine`, `GraphDB`, `TimeSeriesDB` 네 저장 trait 설계가 일관됨
3. **테스트 전략이 올바름** — 각 crate가 stub/mock 구현으로 trait을 테스트하며 외부 서비스에 의존하지 않음
4. **오류 타입 규범화** — `thiserror::Error` derive를 일괄 사용하고 오류 메시지 형식이 일관됨
5. **zero unsafe** — 전체 코드에 unsafe 블록 없음
6. **proc macro 사용 적절** — `Config`와 `Model` 두 derive macro의 책임이 단일함

### 개선 제안

1. **`KvStore` trait을 `&self`로 변경** — `SearchEngine`/`GraphDB`/`TimeSeriesDB`를 벤치마킹, 모두 `&self`를 사용. 내부 가변성은 구현체가 처리 (예: RedisStore의 MultiplexedConnection).

2. **`bee_config_macro`가 section 속성 파싱** — 현재 `"default"` 섹션만 처리하므로 모든 섹션을 순회하고 `#[config(section = "xxx")]`로 중첩 필드를 해당 섹션에 매핑해야 함.

3. **`bee_orm_macro`가 `#[bee(...)]` 속성 파싱** — 현재 테이블명을 구조체명 + "s"로 유추하며 `#[bee(table = "...")]` 속성을 무시함.

4. **`bee_cache::Cache::get`이 `Result<Option<Vec<u8>>>` 반환** — `CacheError`와 일관성 유지. 현재 시그니처 `async fn get(&self, key: &str) -> Option<Vec<u8>>`는 네트워크/직렬화 오류를 삼킴.

5. **통합 테스트 추가** — 현재 모든 테스트가 단위 테스트. `bee_router` + `bee_session` + `bee_cache` 사이에 Session 미들웨어 + 컨트롤러 협업 흐름을 검증하는 통합 테스트 권장.

## 결론

코드 전반의 품질은 양호하며 아키텍처 설계와 crate 분리가 합리적입니다. **핵심 문제는 모두 stub/미완성 상태**이며, 핵심 비즈니스 로직 버그는 적습니다 (bee_logs guard 수명 주기와 bee_cache TTL 누수 두 가지 실제 문제뿐).

프로젝트는 현재 **Phase 6 초기** 단계 — 기반 구조는 완성됐지만 핵심 기능 구현(Router axum 통합, ORM 데이터베이스 백엔드, Config 핫 리로드, 저장 엔진 구체 드라이버)은 후속 작업이 필요합니다.
