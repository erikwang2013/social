## 問題リスト

### 1. 🔴 ルート Cargo.toml の無効な設定項目

**ファイル**: `Cargo.toml:24`  
**問題**: `[workspace.package]` 内の `name = "bee-rust"` は無効なキーで、コンパイルのたびに警告が発生します:

```
warning: /home/wwwroot/bee-rust/Cargo.toml: unused manifest key: workspace.package.name
```

**修正**: `name = "bee-rust"` の行を削除します。workspace レベルのパッケージには name は不要で、各サブ crate の `[package]` にのみ必要です。

---

### 2. 🔴 LICENSE ファイルの欠如

**問題**: ルート `Cargo.toml` は `license = "Apache-2.0"` を宣言していますが、リポジトリのルートに `LICENSE` ファイルがありません。Apache-2.0 ライセンスの条項は、配布物にライセンスの写しを含めることを要求します。

**修正**: ルートディレクトリに Apache-2.0 ライセンス全文を含む `LICENSE` ファイルを作成します。

---

### 3. 🔴 Crate ライセンスメタデータの不整合

以下の crate には `license` フィールドの宣言がありません（crates.io に公開すると「ライセンスなし」と表示されます）:

| Crate | 状態 |
|-------|------|
| bee_cache | ❌ 欠如 |
| bee_cli | ❌ 欠如 |
| bee_graph | ❌ 欠如 |
| bee_kv | ❌ 欠如 |
| bee_logs | ❌ 欠如 |
| bee_rust | ❌ 欠如 |
| bee_search | ❌ 欠如 |
| bee_template | ❌ 欠如 |
| bee_tsdb | ❌ 欠如 |

正しく宣言されている crate: bee_router、bee_config、bee_session、bee_orm、bee_orm_macro

**修正**: 上記 9 個の crate の `Cargo.toml` に `license.workspace = true` を追加します。

---

### 4. 🟡 crates.io 公開メタデータの欠如

すべての crate に以下のフィールドがなく、crates.io での発見性が損なわれています:

- `description` — 簡単な説明
- `repository` — リポジトリのリンク
- `keywords` — 検索キーワード
- `categories` — カテゴリ（例: `["web-programming", "database"]`）

`[workspace.package]` に共通フィールドを追加することを推奨します:

```toml
[workspace.package]
repository = "https://github.com/erikwang2013/bee-rust"
keywords = ["web", "framework", "beego", "mvc"]
categories = ["web-programming"]
```

### 6. 🟡 ストレージエンジンの feature が空のプレースホルダー

以下の feature は宣言されていますが実際の実装がなく、単なる空のプレースホルダーです:

- `bee_search`: `elasticsearch`、`opensearch`、`clickhouse` はすべて `[]`
- `bee_graph`: `neo4j`、`nebulagraph`、`arangodb` はすべて `[]`
- `bee_tsdb`: `influxdb`、`iotdb`、`questdb` はすべて `[]`

つまり README で紹介されている検索エンジン、グラフ DB、時系列 DB のコード例は実際には実行できません（テストも stub を使用しています）。

**提案**: README でこれらの機能を「planned / 計画中」と明記するか、実際のドライバ依存関係と実装を追加します。

---

### 7. 🟡 StubKvStore::expire() は空操作

**ファイル**: `crates/bee_kv/src/lib.rs:111`  
**問題**: テストスタブ `StubKvStore` の `expire()` メソッドは TTL 失効ロジックを実装していませんが、trait はこのインターフェースを定義しています。つまりテストは TTL 関連の挙動をカバーできません。

---

### 8. 🟢 RedisStore の冗長な cfg 注釈

**ファイル**: `crates/bee_kv/src/redis_store.rs`  
**問題**: モジュール全体が `lib.rs` 内の `#[cfg(feature = "redis")]` で既に条件付きコンパイルされているため、`redis_store.rs` 内の `#[cfg(feature = "redis")]` 注釈は冗長です（機能的には正しいが簡潔ではない）。

---

### 9. 🟢 Doc テストの欠如

`bee_template` に 1 件の doc テストがある以外、他のすべての crate にドキュメントテストがありません。コア trait（`Cache`、`KvStore`、`Controller` など）に doc テストの例を追加することを推奨します。

---

### 10. 🟢 bee_graph/src/lib.rs のファイルがやや大きい

406 行で、500 行の制限に近づいています。後日分割を推奨します（例: 独立した model.rs、query.rs）。

## まとめ

プロジェクトのコード品質は総じて良好です。コンパイル通過、テスト全緑、Clippy ゼロ警告、unsafe コードゼロ。アーキテクチャは明確で、trait の抽象化も合理的です。主な問題は**エコシステム設定の完全性**に集中しています — ライセンスファイルの欠如、Cargo.toml メタデータの不完全さ、CI/CD とフォーマット設定の不在。これらの問題は機能には影響しませんが、オープンソースプロジェクトの専門性と crates.io 公開体験には影響します。P0 と P1 の項目を優先的に修正することを推奨します。
