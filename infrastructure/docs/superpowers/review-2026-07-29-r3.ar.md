## المشكلات المكتشفة والمُصلحة في الجولة الثالثة (3 بنود)

### 1. [حرِج] bee_kv/redis_store — تغيير API في redis-rs 0.27.6 يكسر ترجمة `--all-features`

**الملف:** `crates/bee_kv/src/redis_store.rs` (9 مواضع)
**الخطورة:** حرجة — فشل ترجمة `--all-features`

في redis-rs 0.27.6 تغيّر توقيع `redis::Cmd::query_async()` من `&self` إلى `&mut self`. جميع أساليب `RedisStore` التسعة كانت تستخدم `&self.conn.clone()` ويجب تغييرها إلى `&mut self.conn.clone()`.

**الأساليب المتأثرة:** `get`, `set`, `del`, `exists`, `incr` (2), `expire`, `mget`, `mset`

**الإصلاح:**
```rust
// قبل الإصلاح
.query_async(&self.conn.clone())
// بعد الإصلاح
.query_async(&mut self.conn.clone())
```

### 2. [متوسطة] bee_router/filter — تنفيذ SessionFilter الفارغ دون توثيق

**الملف:** `crates/bee_router/src/filter.rs:17-19`
**الخطورة:** متوسطة — قد يظن المستخدم خطأً أن الجلسة قد حُمّلت

ينفّذ `SessionFilter` trait `Filter` لكنه يستخدم التنفيذ الفارغ الافتراضي (`before`/`after` يعيدان مباشرة `Ok(())`). بعد استدعاء هذا الفلتر، قد يظن المستخدم أن الجلسة حُمّلت من الطلب، بينما في الواقع لم يحدث شيء.

**الإصلاح:** تحديث تعليق التوثيق لتوضيح أن هذا تنفيذ مؤقت حاليًا، وأن الجلسة تُنشأ لكل طلب عبر `Context::new()`.

### 3. [منخفضة] bee_template — `_to_json_value` يبتلع أخطاء التسلسل بصمت

**الملف:** `crates/bee_template/src/lib.rs:92`
**الخطورة:** منخفضة — يُستخدم فقط داخل الماكرو `context!`

```rust
// قبل الإصلاح: يعيد Null بصمت عند فشل التسلسل
serde_json::to_value(val).unwrap_or(serde_json::Value::Null)

// بعد الإصلاح: panic مع رسالة خطأ واضحة (مبدأ «أخطاء المبرمج يجب أن تسبب panic»)
serde_json::to_value(val).expect("context! macro values must be serializable")
```

## الخلاصة

اكتشفت الجولة الثالثة بشكل أساسي فشل ترجمة `--all-features` الناتج عن تغيير API في redis-rs 0.27.6 (يؤثر على جميع أساليب عمليات KV التسعة)، بالإضافة إلى نقص التوثيق للتنفيذ الفارغ لـ SessionFilter. جميع المشكلات مُصلحة، وجميع الاختبارات الـ63 ناجحة، وclippy بصفر تحذيرات.

وفي الفترة نفسها اكتمل دمج مكتبة كشف الهجمات security-rust (الإصدار 1.0.4): ينفّذ `SecurityFilter` trait `Filter` لفحص query string لـ URI والترويسات الرئيسية قبل دخول الطلب إلى Controller، ويغطي 27 نوعًا من الهجمات مثل XSS وحقن SQL وحقن الأوامر وSSRF وتجاوز المسارات. أُضيفت 6 اختبارات جديدة لكشف الأمان، يتحكم بها feature gate `security`.

الجودة العامة للمشروع جيدة: صفر كود unsafe، معالجة أخطاء كاملة، اصطلاحات تسمية موحدة، جميع واجهات API العامة موثقة، وكل trait مُختبر. القيود الأربعة المعروفة (مستوى P2/P3) لا تؤثر على الوظائف الحالية، ويُوصى بتحسينها في الإصدارات اللاحقة.
