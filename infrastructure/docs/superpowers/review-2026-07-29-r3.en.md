## Issues Found and Fixed in Round 3 (3 items)

### 1. [Critical] bee_kv/redis_store — redis-rs 0.27.6 API change breaks `--all-features` compilation

**File:** `crates/bee_kv/src/redis_store.rs` (9 places)
**Severity:** Critical — `--all-features` compilation fails

In redis-rs 0.27.6, the signature of `redis::Cmd::query_async()` changed from `&self` to `&mut self`. All 9 methods in `RedisStore` used `&self.conn.clone()` and need to be changed to `&mut self.conn.clone()`.

**Affected methods:** `get`, `set`, `del`, `exists`, `incr` (2), `expire`, `mget`, `mset`

**Fix:**
```rust
// Before
.query_async(&self.conn.clone())
// After
.query_async(&mut self.conn.clone())
```

### 2. [Medium] bee_router/filter — SessionFilter empty implementation without documentation

**File:** `crates/bee_router/src/filter.rs:17-19`
**Severity:** Medium — users may wrongly assume the session has been loaded

`SessionFilter` implements the `Filter` trait but uses the default empty implementation (`before`/`after` return `Ok(())` directly). After calling this filter, users may assume the session has been loaded from the request, but in fact nothing has happened.

**Fix:** Update the documentation comment to clarify that this is currently a placeholder implementation and the session is created per-request by `Context::new()`.

### 3. [Low] bee_template — `_to_json_value` silently swallows serialization errors

**File:** `crates/bee_template/src/lib.rs:92`
**Severity:** Low — only used inside the `context!` macro

```rust
// Before: silently returns Null when serialization fails
serde_json::to_value(val).unwrap_or(serde_json::Value::Null)

// After: panics with a clear error message (per the "programmer errors should panic" principle)
serde_json::to_value(val).expect("context! macro values must be serializable")
```

## Summary

Round 3 mainly found the `--all-features` compilation failure caused by the redis-rs 0.27.6 API change (affecting all 9 KV operation methods), as well as the missing documentation for the SessionFilter empty implementation. All issues have been fixed, all 63 tests pass, and clippy reports zero warnings.

In the same period, the security-rust (v1.0.4) attack detection library was integrated: through `SecurityFilter` implementing the `Filter` trait, the URI query string and key headers are scanned before the request enters the Controller, covering 27 attack types including XSS, SQL injection, command injection, SSRF, and path traversal. 6 new security detection tests were added, controlled by the `security` feature gate.

Overall project quality is good: zero unsafe code, complete error handling, consistent naming conventions, all public APIs documented, and every trait tested. The 4 known limitations (P2/P3 level) do not affect current functionality and are recommended for improvement in later versions.
