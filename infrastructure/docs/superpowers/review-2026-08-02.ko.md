## 문제 목록

### 1. 🔴 루트 Cargo.toml의 잘못된 구성 항목

**파일**: `Cargo.toml:24`  
**문제**: `[workspace.package]`의 `name = "bee-rust"`는 잘못된 키로, 컴파일할 때마다 warning이 발생합니다:

```
warning: /home/wwwroot/bee-rust/Cargo.toml: unused manifest key: workspace.package.name
```

**수정**: `name = "bee-rust"` 줄을 삭제합니다. workspace 레벨의 package에는 name이 필요 없으며, 각 하위 crate의 `[package]`에만 필요합니다.

---

### 2. 🔴 LICENSE 파일 없음

**문제**: 루트 `Cargo.toml`에 `license = "Apache-2.0"`이 선언되어 있지만 저장소 루트에 `LICENSE` 파일이 없습니다. Apache-2.0 라이선스 조항은 배포물에 라이선스 사본을 포함할 것을 요구합니다.

**수정**: 루트 디렉터리에 Apache-2.0 라이선스 전문이 담긴 `LICENSE` 파일을 생성합니다.

---

### 4. 🟡 crates.io 게시 메타데이터 누락

모든 crate에 다음 필드가 없어 crates.io에서의 발견 가능성이 낮습니다:

- `description` — 간단한 설명
- `repository` — 코드 저장소 링크
- `keywords` — 검색 키워드
- `categories` — 분류 (예: `["web-programming", "database"]`)

`[workspace.package]`에 공통 필드를 추가할 것을 권장합니다:

```toml
[workspace.package]
repository = "https://github.com/erikwang2013/bee-rust"
keywords = ["web", "framework", "beego", "mvc"]
categories = ["web-programming"]
```

### 6. 🟡 스토리지 엔진 feature가 빈 플레이스홀더

다음 feature는 선언만 되어 있고 실제 구현이 없어 빈 플레이스홀더에 불과합니다:

- `bee_search`: `elasticsearch`, `opensearch`, `clickhouse` 모두 `[]`
- `bee_graph`: `neo4j`, `nebulagraph`, `arangodb` 모두 `[]`
- `bee_tsdb`: `influxdb`, `iotdb`, `questdb` 모두 `[]`

즉 README에 소개된 검색 엔진, 그래프 DB, 시계열 DB 코드 예제는 실제로 실행할 수 없습니다 (테스트도 stub을 사용합니다).

**제안**: README에서 이러한 기능을 "계획 중 / planned"으로 표시하거나, 실제 드라이버 의존성과 구현을 추가합니다.

### 7. 🟡 StubKvStore::expire()는 빈 동작

**파일**: `crates/bee_kv/src/lib.rs:111`  
**문제**: 테스트 스텁 `StubKvStore`의 `expire()` 메서드가 TTL 만료 로직을 구현하지 않지만, trait은 이 인터페이스를 정의합니다. 즉 테스트가 TTL 관련 동작을 검증할 수 없습니다.

---

### 8. 🟢 RedisStore의 중복 cfg 어노테이션

**파일**: `crates/bee_kv/src/redis_store.rs`  
**문제**: 모듈 전체가 이미 `lib.rs`에서 `#[cfg(feature = "redis")]`로 조건부 컴파일되고 있는데, `redis_store.rs` 내부의 `#[cfg(feature = "redis")]` 어노테이션은 중복입니다 (기능은 정확하지만 간결하지 않음).

---

### 9. 🟢 Doc-test 부족

`bee_template`에 doc-test 1개가 있는 것 외에 나머지 모든 crate에는 문서 테스트가 없습니다. 핵심 trait(`Cache`, `KvStore`, `Controller` 등)에 doc-test 예제를 추가할 것을 권장합니다.

## 요약

프로젝트의 전반적인 코드 품질은 양호합니다: 컴파일 통과, 테스트 전체 통과, Clippy 경고 0, unsafe 코드 0건. 아키텍처가 명확하고 trait 추상화가 합리적입니다. 주요 문제는 **생태계 구성의 완성도**에 집중되어 있습니다 — 라이선스 파일 누락, Cargo.toml 메타데이터 불완전, CI/CD 및 포맷 구성 부재. 이러한 문제는 기능에 영향을 주지 않지만 오픈소스 프로젝트의 전문성과 crates.io 게시 경험에는 영향을 줍니다. P0과 P1 항목을 우선 수정할 것을 권장합니다.
