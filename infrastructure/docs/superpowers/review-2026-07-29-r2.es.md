## Correcciones de la primera ronda (8 elementos)

### 1. bee_kv — palabra clave `mut` innecesaria (aviso de compilación)

**Archivo:** `crates/bee_kv/src/lib.rs:129,136,145,158`
**Gravedad:** baja

Todos los métodos de `StubKvStore` se invocan mediante `&self` (Mutex internamente), por lo que `let mut store` en las pruebas no necesita `mut`. Cambiado a `let store`.

### 2. bee_router — `unwrap()` en `into_response()` podría causar pánico

**Archivo:** `crates/bee_router/src/context.rs:119`
**Gravedad:** media

`builder.body(...).unwrap()` — aunque los valores de cabecera se construyen internamente y no contienen caracteres no válidos, esto viola la regla de «prohibido el pánico en código de bibliotecas». Se cambió a `expect()` con un comentario SAFETY que explica el motivo.

### 3. bee_router — campo `query_map` sin usar

**Archivo:** `crates/bee_router/src/context.rs:22`
**Gravedad:** baja

El campo `query_map: HashMap<String, String>` estaba declarado con `#[allow(dead_code)]` pero nunca se usó. Eliminado según el principio YAGNI.

### 4. bee_logs — conflicto de inicialización repetida del subscriber tracing en las pruebas

**Archivo:** `crates/bee_logs/src/lib.rs:100-116`
**Gravedad:** media

`test_logger_stdout` y `test_logger_default` llaman ambas a `init()`, y `tracing_subscriber::try_init()` solo puede tener éxito una vez a nivel global. Se usó `std::sync::Once` para garantizar una única inicialización, y se añadió la prueba `test_level_str` para cubrir el método `level_str()`.

### 5. bee_tsdb — 3 `map_or` simplificables (Clippy)

**Archivo:** `crates/bee_tsdb/src/lib.rs:198,199,200-203`
**Gravedad:** baja

```rust
// Antes de la corrección
p.tags.get(&f.key).map_or(false, |v| v == &f.value)
// Después de la corrección
p.tags.get(&f.key) == Some(&f.value)
```

### 6. bee_graph — `for_kv_map` simplificable a `values()` (Clippy)

**Archivo:** `crates/bee_graph/src/lib.rs:241`
**Gravedad:** baja

`for (_eid, edge) in emap.iter()` → `for edge in emap.values()`

### 7. bee_rust — `needless_question_mark` (Clippy)

**Archivo:** `crates/bee_rust/src/lib.rs:37`
**Gravedad:** baja

`Ok(bee_logs::Logger::new().init()?)` → `bee_logs::Logger::new().init()`

### 8. bee_router — el trait Filter carece de comentarios de documentación

**Archivo:** `crates/bee_router/src/filter.rs:4`
**Gravedad:** baja

Se añadieron comentarios de documentación al trait `Filter`.

## Correcciones de la segunda ronda — todos los puntos ABCDE tratados (5)

### A. bee_orm — riesgo de inyección SQL en `to_sql()` ✅ corregido

**Archivo:** `crates/bee_orm/src/lib.rs:63`
**Gravedad:** alta (potencial)

`to_sql()` concatena directamente cadenas crudas en el SQL. Se añadió un **Warning** en el comentario de documentación del método: solo sirve para depuración y pruebas, y los controladores de backend deben usar consultas parametrizadas.

### B. bee_config_macro — `unwrap_or` se traga silenciosamente los errores de análisis ✅ corregido

**Archivo:** `crates/bee_config_macro/src/lib.rs:21-27`
**Gravedad:** baja

`unwrap_or` se cambió a `unwrap_or_else`, con comentarios ampliados: los valores no JSON (como `dev`, `localhost`) se degradan correctamente a cadenas JSON; si un valor contiene un error tipográfico (como `8o8o`), se almacena como cadena y `serde_json::from_value` genera un error claro de desajuste de tipos.

### C. bee_cli — sin cobertura de pruebas ✅ corregido

**Archivo:** `crates/bee_cli/src/main.rs`
**Gravedad:** media

Se añadieron **9** pruebas unitarias de análisis de argumentos CLI que cubren todos los subcomandos:

- `test_new_command` — creación de proyecto
- `test_generate_controller` / `test_generate_model` — generación de código
- `test_run_command` / `test_run_watch` — servidor de desarrollo
- `test_migrate_up` / `test_migrate_down` — migraciones de base de datos
- `test_pack_default_target` / `test_pack_custom_target` — empaquetado y despliegue

### D. Router/RouteGroup sin comentarios de documentación ✅ corregido

**Archivo:** `crates/bee_router/src/router.rs:5,44`
**Gravedad:** baja

Se añadieron comentarios de documentación a las estructuras `Router` y `RouteGroup`.

### E. redis_store — clone innecesario de MultiplexedConnection ✅ analizado

**Archivo:** `crates/bee_kv/src/redis_store.rs`
**Gravedad:** baja

El análisis confirmó: `redis::Cmd::query_async` exige una referencia `&mut`, y `self.conn.clone()` es el uso estándar de la crate redis-rs. `MultiplexedConnection::clone()` solo incrementa el contador de referencias, con un coste insignificante. **No requiere cambios.**
