## तीसरे दौर में पाई गई और ठीक की गई समस्याएं (3 मदें)

### 1. [गंभीर] bee_kv/redis_store — redis-rs 0.27.6 API बदलाव से `--all-features` कंपाइलेशन विफल

**फ़ाइल:** `crates/bee_kv/src/redis_store.rs` (9 स्थान)
**गंभीरता:** गंभीर — `--all-features` कंपाइलेशन विफल

redis-rs 0.27.6 में `redis::Cmd::query_async()` का सिग्नेचर `&self` से बदलकर `&mut self` कर दिया गया। `RedisStore` के सभी 9 मेथड `&self.conn.clone()` उपयोग करते थे, इन्हें `&mut self.conn.clone()` में बदलना होगा।

**प्रभावित मेथड:** `get`, `set`, `del`, `exists`, `incr` (2), `expire`, `mget`, `mset`

**सुधार:**
```rust
// सुधार से पहले
.query_async(&self.conn.clone())
// सुधार के बाद
.query_async(&mut self.conn.clone())
```

### 2. [मध्यम] bee_router/filter — SessionFilter की खाली इम्प्लीमेंटेशन में दस्तावेज़ीकरण नहीं

**फ़ाइल:** `crates/bee_router/src/filter.rs:17-19`
**गंभीरता:** मध्यम — उपयोगकर्ता गलती से मान सकता है कि session लोड हो गया

`SessionFilter` `Filter` trait को इम्प्लीमेंट करता है लेकिन डिफ़ॉल्ट खाली इम्प्लीमेंटेशन उपयोग करता है (`before`/`after` सीधे `Ok(())` लौटाते हैं)। इस फ़िल्टर को कॉल करने के बाद उपयोगकर्ता सोच सकता है कि session अनुरोध से लोड हो गया है, जबकि वास्तव में कुछ नहीं हुआ।

**सुधार:** दस्तावेज़ीकरण कमेंट अपडेट करें और स्पष्ट करें कि यह वर्तमान में एक प्लेसहोल्डर इम्प्लीमेंटेशन है और session प्रति-अनुरोध `Context::new()` द्वारा बनाया जाता है।

### 3. [निम्न] bee_template — `_to_json_value` सीरियलाइज़ेशन त्रुटियों को चुपचाप निगल जाता है

**फ़ाइल:** `crates/bee_template/src/lib.rs:92`
**गंभीरता:** निम्न — केवल `context!` मैक्रो के अंदर उपयोग होता है

```rust
// सुधार से पहले: सीरियलाइज़ेशन विफल होने पर चुपचाप Null लौटाता है
serde_json::to_value(val).unwrap_or(serde_json::Value::Null)

// सुधार के बाद: स्पष्ट त्रुटि संदेश के साथ panic («प्रोग्रामर त्रुटियों पर panic होना चाहिए» सिद्धांत)
serde_json::to_value(val).expect("context! macro values must be serializable")
```

## सारांश

तीसरे दौर में मुख्य रूप से redis-rs 0.27.6 API बदलाव से उत्पन्न `--all-features` कंपाइलेशन विफलता (सभी 9 KV ऑपरेशन मेथड्स को प्रभावित करने वाली) और SessionFilter की खाली इम्प्लीमेंटेशन में दस्तावेज़ीकरण की कमी पाई गई। सभी समस्याएं ठीक कर दी गई हैं, सभी 63 टेस्ट पास हैं और clippy में शून्य चेतावनी है।

इसी अवधि में security-rust (v1.0.4) आक्रमण-पहचान लाइब्रेरी का एकीकरण पूरा हुआ: `SecurityFilter` `Filter` trait को इम्प्लीमेंट करके अनुरोध Controller में प्रवेश करने से पहले URI query string और प्रमुख headers की जांच करता है, जिसमें XSS, SQL इंजेक्शन, कमांड इंजेक्शन, SSRF, पाथ ट्रैवर्सल आदि 27 प्रकार के आक्रमण शामिल हैं। 6 नए सुरक्षा-पहचान टेस्ट जोड़े गए, जो `security` feature gate द्वारा नियंत्रित हैं।

प्रोजेक्ट की समग्र गुणवत्ता अच्छी है: शून्य unsafe कोड, पूर्ण त्रुटि प्रबंधन, समान नामकरण परंपराएँ, सभी सार्वजनिक API दस्तावेज़ीकृत और हर trait परीक्षित। 4 ज्ञात सीमाएँ (P2/P3 स्तर) वर्तमान कार्यक्षमता को प्रभावित नहीं करतीं, बाद के संस्करणों में सुधार की अनुशंसा की जाती है।
