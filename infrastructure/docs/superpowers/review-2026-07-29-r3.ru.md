## Проблемы, обнаруженные и исправленные в третьем раунде (3 шт.)

### 1. [Критично] bee_kv/redis_store — изменение API redis-rs 0.27.6 ломает сборку `--all-features`

**Файл:** `crates/bee_kv/src/redis_store.rs` (9 мест)
**Серьёзность:** Критично — сборка `--all-features` не проходит

В redis-rs 0.27.6 сигнатура `redis::Cmd::query_async()` изменилась с `&self` на `&mut self`. Все 9 методов `RedisStore` использовали `&self.conn.clone()` — их нужно изменить на `&mut self.conn.clone()`.

**Затронутые методы:** `get`, `set`, `del`, `exists`, `incr` (2), `expire`, `mget`, `mset`

**Исправление:**
```rust
// До исправления
.query_async(&self.conn.clone())
// После исправления
.query_async(&mut self.conn.clone())
```

### 2. [Средне] bee_router/filter — пустая реализация SessionFilter без документации

**Файл:** `crates/bee_router/src/filter.rs:17-19`
**Серьёзность:** Средне — пользователь может ошибочно предположить, что сессия загружена

`SessionFilter` реализует trait `Filter`, но использует пустую реализацию по умолчанию (`before`/`after` сразу возвращают `Ok(())`). Вызвав этот фильтр, пользователь может решить, что сессия загружена из запроса, хотя на самом деле ничего не произошло.

**Исправление:** Обновить комментарий документации, указав, что это временная реализация-заглушка, а сессия создаётся для каждого запроса методом `Context::new()`.

### 3. [Низко] bee_template — `_to_json_value` молча поглощает ошибки сериализации

**Файл:** `crates/bee_template/src/lib.rs:92`
**Серьёзность:** Низко — используется только внутри макроса `context!`

```rust
// До исправления: при сбое сериализации молча возвращает Null
serde_json::to_value(val).unwrap_or(serde_json::Value::Null)

// После исправления: panic с понятным сообщением (принцип «ошибки программиста должны вызывать panic»)
serde_json::to_value(val).expect("context! macro values must be serializable")
```

## Аудит качества кода (наблюдения без изменения кода)

### Известные ограничения (рекомендуется улучшить в следующих версиях)

| # | Место | Описание | Приоритет |
|---|------|------|--------|
| 1 | `bee_router/router.rs` | `Handler<T, ()>` использует параметр типа `()`, поэтому обработчики не могут использовать экстракторы axum (State/Query/Path и т. д.) | P2 |
| 2 | `bee_config_macro` | `reload()` и `watch()` генерируют пустые реализации, что противоречит описанию «перезагрузка» и «отслеживание изменений» в документации trait | P2 |
| 3 | `bee_rust/prelude` | Экспорт `bee_config::Config` — это derive-макрос, а не trait `ConfigSource`; имя может вводить пользователей в заблуждение | P3 |
| 4 | `bee_orm/QuerySet` | Обобщение `T` не имеет trait-bound, `PhantomData<T>` используется только как маркер типа | P3 |

### Положительная оценка

- **Обработка ошибок:** Все crate используют деривацию `thiserror::Error`, типы ошибок определены чётко
- **Feature gate:** `bee_kv/redis_store` корректно использует `#[cfg(feature = "redis")]`
- **Покрытие тестами:** Для каждого trait есть соответствующая заглушка и тесты
- **Документация:** Все публичные типы и методы trait имеют комментарии `///`
- **Асинхронная безопасность:** Корректно используется `tokio::sync::RwLock`, блокирующие вызовы не смешаны с асинхронным контекстом
- **Ноль unsafe:** Во всём проекте нет ни одного unsafe
- **Ноль unwrap:** В библиотечном коде есть только `expect()` с комментариями SAFETY

## Резюме

В третьем раунде в основном обнаружен сбой сборки `--all-features` из-за изменения API redis-rs 0.27.6 (затронуты все 9 методов операций KV), а также отсутствие документации для пустой реализации SessionFilter. Все проблемы исправлены, все 63 теста проходят, clippy — ноль предупреждений.

В тот же период выполнена интеграция библиотеки обнаружения атак security-rust (v1.0.4): `SecurityFilter` реализует trait `Filter` и сканирует query string URI и ключевые заголовки до входа запроса в Controller, покрывая 27 типов атак, включая XSS, SQL-инъекции, инъекции команд, SSRF и обход пути. Добавлено 6 новых тестов обнаружения безопасности, управляемых feature gate `security`.

Общее качество проекта хорошее: ноль unsafe-кода, полная обработка ошибок, единые соглашения об именовании, документированы все публичные API, каждый trait покрыт тестами. 4 известных ограничения (уровень P2/P3) не влияют на текущую функциональность; их рекомендуется улучшить в следующих версиях.
