## তৃতীয় রাউন্ডে পাওয়া ও ঠিক করা সমস্যা (৩টি)

### ১. [গুরুতর] bee_kv/redis_store — redis-rs 0.27.6 API পরিবর্তনে `--all-features` কম্পাইল ব্যর্থ

**ফাইল:** `crates/bee_kv/src/redis_store.rs` (৯ জায়গায়)
**গুরুতরতা:** গুরুতর — `--all-features` কম্পাইল ব্যর্থ

redis-rs 0.27.6-এ `redis::Cmd::query_async()`-এর সিগনেচার `&self` থেকে `&mut self`-এ পরিবর্তিত হয়েছে। `RedisStore`-এর সব ৯টি মেথড `&self.conn.clone()` ব্যবহার করত, এগুলোকে `&mut self.conn.clone()`-এ বদলাতে হবে।

**প্রভাবিত মেথড:** `get`, `set`, `del`, `exists`, `incr` (2), `expire`, `mget`, `mset`

**সমাধান:**
```rust
// সমাধানের আগে
.query_async(&self.conn.clone())
// সমাধানের পরে
.query_async(&mut self.conn.clone())
```

### ২. [মাঝারি] bee_router/filter — SessionFilter-এর খালি ইমপ্লিমেন্টেশনে ডকুমেন্টেশন নেই

**ফাইল:** `crates/bee_router/src/filter.rs:17-19`
**গুরুতরতা:** মাঝারি — ব্যবহারকারী ভুল করে মনে করতে পারেন session লোড হয়েছে

`SessionFilter` `Filter` trait ইমপ্লিমেন্ট করে কিন্তু ডিফল্ট খালি ইমপ্লিমেন্টেশন ব্যবহার করে (`before`/`after` সরাসরি `Ok(())` ফেরত দেয়)। এই ফিল্টার কল করার পর ব্যবহারকারী মনে করতে পারেন session রিকোয়েস্ট থেকে লোড হয়েছে, অথচ আসলে কিছুই ঘটেনি।

**সমাধান:** ডকুমেন্টেশন কমেন্ট আপডেট করে পরিষ্কারভাবে জানাতে হবে যে এটি বর্তমানে একটি প্লেসহোল্ডার ইমপ্লিমেন্টেশন এবং session প্রতি-রিকোয়েস্ট `Context::new()` দ্বারা তৈরি হয়।

### ৩. [কম] bee_template — `_to_json_value` নীরবে সিরিয়ালাইজেশন ত্রুটি গিলে ফেলে

**ফাইল:** `crates/bee_template/src/lib.rs:92`
**গুরুতরতা:** কম — শুধু `context!` ম্যাক্রোর ভেতরে ব্যবহৃত

```rust
// সমাধানের আগে: সিরিয়ালাইজেশন ব্যর্থ হলে নীরবে Null ফেরত দেয়
serde_json::to_value(val).unwrap_or(serde_json::Value::Null)

// সমাধানের পরে: স্পষ্ট ত্রুটি বার্তাসহ panic («প্রোগ্রামারের ত্রুটিতে panic হওয়া উচিত» নীতি)
serde_json::to_value(val).expect("context! macro values must be serializable")
```

## সারসংক্ষেপ

তৃতীয় রাউন্ডে মূলত redis-rs 0.27.6 API পরিবর্তনের কারণে `--all-features` কম্পাইল ব্যর্থতা (সব ৯টি KV অপারেশন মেথডকে প্রভাবিত) এবং SessionFilter-এর খালি ইমপ্লিমেন্টেশনে ডকুমেন্টেশনের অভাব পাওয়া গেছে। সব সমস্যা ঠিক করা হয়েছে, সব ৬৩টি টেস্ট পাস এবং clippy-তে শূন্য সতর্কতা।

একই সময়ে security-rust (v1.0.4) আক্রমণ-শনাক্তকরণ লাইব্রেরির ইন্টিগ্রেশন সম্পন্ন হয়েছে: `SecurityFilter` `Filter` trait ইমপ্লিমেন্ট করে রিকোয়েস্ট Controller-এ ঢোকার আগে URI query string ও গুরুত্বপূর্ণ headers স্ক্যান করে, যার আওতায় XSS, SQL ইনজেকশন, কমান্ড ইনজেকশন, SSRF, পাথ ট্রাভার্সালসহ ২৭ ধরনের আক্রমণ। ৬টি নতুন সিকিউরিটি ডিটেকশন টেস্ট যোগ করা হয়েছে, `security` feature gate দিয়ে নিয়ন্ত্রিত।

প্রজেক্টের সামগ্রিক মান ভালো: শূন্য unsafe কোড, পূর্ণাঙ্গ ত্রুটি হ্যান্ডলিং, অভিন্ন নামকরণ রীতি, সব পাবলিক API ডকুমেন্টেড এবং প্রতিটি trait পরীক্ষিত। ৪টি জানা সীমাবদ্ধতা (P2/P3 স্তর) বর্তমান ফিচারে প্রভাব ফেলে না; পরবর্তী ভার্সনে উন্নতির সুপারিশ করা হয়।
