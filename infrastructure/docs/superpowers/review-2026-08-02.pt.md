## Lista de problemas

### 1. 🔴 Item de configuração inválido no Cargo.toml raiz

**Arquivo**: `Cargo.toml:24`  
**Problema**: `name = "bee-rust"` em `[workspace.package]` é uma chave inválida que gera um aviso a cada compilação:

```
warning: /home/wwwroot/bee-rust/Cargo.toml: unused manifest key: workspace.package.name
```

**Correção**: remover a linha `name = "bee-rust"`. Um pacote no nível do workspace não precisa de nome; apenas o `[package]` de cada sub-crate precisa.

---

### 2. 🔴 Arquivo LICENSE ausente

**Problema**: o `Cargo.toml` raiz declara `license = "Apache-2.0"`, mas não há arquivo `LICENSE` na raiz do repositório. Os termos da licença Apache-2.0 exigem incluir uma cópia da licença nas distribuições.

**Correção**: criar na raiz um arquivo `LICENSE` com o texto completo da licença Apache-2.0.

---

### 3. 🔴 Metadados de licença inconsistentes entre crates

Os seguintes crates não possuem o campo `license` declarado (aparecerão como «sem licença» ao publicar no crates.io):

| Crate | Status |
|-------|------|
| bee_cache | ❌ Ausente |
| bee_cli | ❌ Ausente |
| bee_graph | ❌ Ausente |
| bee_kv | ❌ Ausente |
| bee_logs | ❌ Ausente |
| bee_rust | ❌ Ausente |
| bee_search | ❌ Ausente |
| bee_template | ❌ Ausente |
| bee_tsdb | ❌ Ausente |

Crates com licença corretamente declarada: bee_router, bee_config, bee_session, bee_orm, bee_orm_macro

**Correção**: adicionar `license.workspace = true` no `Cargo.toml` dos 9 crates acima.

---

### 4. 🟡 Metadados de publicação no crates.io ausentes

Todos os crates não possuem os seguintes campos, o que prejudica a descoberta no crates.io:

- `description` — descrição breve
- `repository` — link do repositório
- `keywords` — palavras-chave de busca
- `categories` — categorias (ex.: `["web-programming", "database"]`)

Recomenda-se adicionar campos comuns em `[workspace.package]`:

```toml
[workspace.package]
repository = "https://github.com/erikwang2013/bee-rust"
keywords = ["web", "framework", "beego", "mvc"]
categories = ["web-programming"]
```

### 6. 🟡 Features de mecanismos de armazenamento são placeholders vazios

As seguintes features estão declaradas mas não têm implementação real, servindo apenas como placeholders vazios:

- `bee_search`: `elasticsearch`, `opensearch`, `clickhouse` são todas `[]`
- `bee_graph`: `neo4j`, `nebulagraph`, `arangodb` são todas `[]`
- `bee_tsdb`: `influxdb`, `iotdb`, `questdb` são todas `[]`

Isso significa que os exemplos de código do README para mecanismos de busca, bancos de grafos e bancos de séries temporais não podem ser executados de verdade (seus testes também usam stubs).

**Sugestão**: marcar essas funções como «planned / planejadas» no README, ou adicionar dependências reais de drivers e implementações.

---

### 7. 🟡 StubKvStore::expire() é uma operação vazia

**Arquivo**: `crates/bee_kv/src/lib.rs:111`  
**Problema**: o método `expire()` do stub de teste `StubKvStore` não implementa a lógica de expiração TTL, embora o trait defina essa interface. Os testes não podem cobrir o comportamento relacionado a TTL.

---

### 8. 🟢 Anotação cfg redundante no RedisStore

**Arquivo**: `crates/bee_kv/src/redis_store.rs`  
**Problema**: o módulo inteiro já é compilado condicionalmente via `#[cfg(feature = "redis")]` em `lib.rs`; a anotação `#[cfg(feature = "redis")]` dentro de `redis_store.rs` é redundante (funcionalmente correta, mas não concisa).

---

### 9. 🟢 Doc-tests ausentes

Além de `bee_template`, que tem 1 doc-test, nenhum dos outros crates tem testes de documentação. Recomenda-se adicionar exemplos de doc-tests para os traits principais (`Cache`, `KvStore`, `Controller`, etc.).

---

### 10. 🟢 bee_graph/src/lib.rs é um pouco grande

406 linhas, próximo do limite de 500 linhas. Recomenda-se dividir futuramente (ex.: model.rs, query.rs separados).

## Resumo

A qualidade geral do código do projeto é boa: compilação aprovada, testes totalmente verdes, Clippy sem avisos e zero código unsafe. A arquitetura é clara e as abstrações de traits são razoáveis. Os principais problemas se concentram na **integridade da configuração do ecossistema** — arquivo de licença ausente, metadados Cargo.toml incompletos e falta de configuração de CI/CD e de formatação. Esses problemas não afetam a funcionalidade, mas afetam o profissionalismo do projeto de código aberto e a experiência de publicação no crates.io. Recomenda-se corrigir primeiro os itens P0 e P1.
