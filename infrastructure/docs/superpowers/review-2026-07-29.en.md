## Issues Fixed

### BUG-001: bee_logs — `WorkerGuard` dropped immediately causing async log loss

**Severity:** High  
**File:** `crates/bee_logs/src/lib.rs:54,62`

The `WorkerGuard` returned by `tracing_appender::non_blocking()` is dropped at the end of the `match` branch,
which immediately stops the non-blocking writer worker thread and loses all async log messages.

**Fix:** Added a `LogHandle` struct holding `Option<WorkerGuard>`; `Logger::init()` now returns
`Result<LogHandle, ...>`. Callers must keep the `LogHandle` alive to ensure continued writing.

### BUG-002: bee_cache — memory leak of TTL-expired entries

**Severity:** Medium  
**File:** `crates/bee_cache/src/lib.rs:60-71`

`MemoryCache::get()` only returns `None` when it detects TTL expiry, without removing the entry from the HashMap.
In long-running applications, expired entries keep accumulating, causing a memory leak.

**Fix:** `get()` releases the read lock, acquires the write lock, and deletes the expired entry after detecting expiry.

### BUG-003: examples/hello — unused import warning

**Severity:** Low  
**File:** `examples/hello/src/main.rs:1`

`use bee_rust::prelude::*` is unused and produces a compile warning.

**Fix:** Removed the import and bound the `init()` return value to `_log_handle` to prevent the LogHandle from being dropped early.

## Architecture Observations

### Highlights

1. **Clear crate split** — 15 crates with clear responsibilities and sensible dependency direction (foundation → storage → web → aggregation)
2. **Complete trait abstractions** — the four storage traits `KvStore`, `SearchEngine`, `GraphDB`, `TimeSeriesDB` are designed consistently
3. **Correct testing strategy** — each crate tests its trait with stub/mock implementations, no external service dependency
4. **Standardized error types** — uniform use of `thiserror::Error` derive, consistent error message formatting
5. **Zero unsafe** — no unsafe blocks in the entire codebase
6. **Proper proc macro usage** — the two derive macros `Config` and `Model` have single responsibilities

### Improvement Suggestions

1. **`KvStore` trait should use `&self`** — benchmark against `SearchEngine`/`GraphDB`/`TimeSeriesDB`, which all use `&self`. Interior mutability is handled by the implementations themselves (e.g., RedisStore's MultiplexedConnection).

2. **`bee_config_macro` should parse the section attribute** — currently only handles the `"default"` section; it needs to iterate all sections and use `#[config(section = "xxx")]` to map nested fields to their sections.

3. **`bee_orm_macro` should parse the `#[bee(...)]` attribute** — the current table name is derived from the struct name + "s", ignoring the `#[bee(table = "...")]` attribute.

4. **`bee_cache::Cache::get` should return `Result<Option<Vec<u8>>>`** — consistent with `CacheError`. The current signature `async fn get(&self, key: &str) -> Option<Vec<u8>>` swallows network/serialization errors.

5. **Add integration tests** — all current tests are unit tests. Add integration tests across `bee_router` + `bee_session` + `bee_cache` to verify the Session middleware + controller collaboration flow.

## Conclusion

Overall code quality is good, and the architecture design and crate split are reasonable. **The key issues are all stubs/unfinished states**, with few core business logic bugs (only two real problems: the bee_logs guard lifecycle and the bee_cache TTL leak).

The project is currently at **early Phase 6** — the foundation structure is complete, but key feature implementations (Router axum integration, ORM database backends, Config hot reload, concrete storage engine drivers) still need follow-up tasks.
