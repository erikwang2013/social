## Perbaikan Putaran Pertama (8 item)

### 1. bee_kv — kata kunci `mut` yang tidak perlu (peringatan kompilasi)

**Berkas:** `crates/bee_kv/src/lib.rs:129,136,145,158`
**Tingkat keparahan:** rendah

Semua metode `StubKvStore` dipanggil melalui `&self` (memakai Mutex di dalamnya), jadi `let mut store` dalam pengujian tidak butuh `mut`. Diubah menjadi `let store`.

### 2. bee_router — `unwrap()` di `into_response()` dapat menyebabkan panic

**Berkas:** `crates/bee_router/src/context.rs:119`
**Tingkat keparahan:** sedang

`builder.body(...).unwrap()` — meski nilai header dibangun internal sehingga tidak mengandung karakter tidak valid, ini melanggar aturan «dilarang panic pada kode pustaka». Diubah menjadi `expect()` dengan komentar SAFETY yang menjelaskan alasannya.

### 3. bee_router — field `query_map` tak terpakai

**Berkas:** `crates/bee_router/src/context.rs:22`
**Tingkat keparahan:** rendah

Field `query_map: HashMap<String, String>` dideklarasikan dengan `#[allow(dead_code)]` tetapi tidak pernah digunakan. Dihapus sesuai prinsip YAGNI.

### 4. bee_logs — konflik inisialisasi berulang tracing subscriber dalam pengujian

**Berkas:** `crates/bee_logs/src/lib.rs:100-116`
**Tingkat keparahan:** sedang

`test_logger_stdout` dan `test_logger_default` sama-sama memanggil `init()`, padahal `tracing_subscriber::try_init()` hanya dapat berhasil sekali secara global. `std::sync::Once` dipakai untuk memastikan inisialisasi hanya sekali, dan ditambahkan pengujian `test_level_str` untuk menutup metode `level_str()`.

### 5. bee_tsdb — 3 `map_or` dapat disederhanakan (Clippy)

**Berkas:** `crates/bee_tsdb/src/lib.rs:198,199,200-203`
**Tingkat keparahan:** rendah

```rust
// Sebelum perbaikan
p.tags.get(&f.key).map_or(false, |v| v == &f.value)
// Setelah perbaikan
p.tags.get(&f.key) == Some(&f.value)
```

### 6. bee_graph — `for_kv_map` dapat disederhanakan menjadi `values()` (Clippy)

**Berkas:** `crates/bee_graph/src/lib.rs:241`
**Tingkat keparahan:** rendah

`for (_eid, edge) in emap.iter()` → `for edge in emap.values()`

### 7. bee_rust — `needless_question_mark` (Clippy)

**Berkas:** `crates/bee_rust/src/lib.rs:37`
**Tingkat keparahan:** rendah

`Ok(bee_logs::Logger::new().init()?)` → `bee_logs::Logger::new().init()`

### 8. bee_router — trait Filter tanpa komentar dokumentasi

**Berkas:** `crates/bee_router/src/filter.rs:4`
**Tingkat keparahan:** rendah

Komentar dokumentasi ditambahkan untuk trait `Filter`.

## Perbaikan Putaran Kedua — semua poin ABCDE ditangani (5)

### A. bee_orm — risiko injeksi SQL pada `to_sql()` ✅ diperbaiki

**Berkas:** `crates/bee_orm/src/lib.rs:63`
**Tingkat keparahan:** tinggi (potensial)

`to_sql()` menempelkan string mentah langsung ke SQL. Ditambahkan **Warning** pada komentar dokumentasi metode: metode ini hanya untuk debugging dan pengujian, dan driver backend wajib memakai kueri terparameterisasi.

### B. bee_config_macro — `unwrap_or` menelan kesalahan parsing secara diam-diam ✅ diperbaiki

**Berkas:** `crates/bee_config_macro/src/lib.rs:21-27`
**Tingkat keparahan:** rendah

`unwrap_or` diubah menjadi `unwrap_or_else` dengan komentar yang diperluas: nilai non-JSON (seperti `dev`, `localhost`) benar-benar jatuh kembali ke string JSON; jika nilai mengandung salah ketik (seperti `8o8o`), nilai tersimpan sebagai string dan `serde_json::from_value` menghasilkan kesalahan ketidakcocokan tipe yang jelas.

### C. bee_cli — tidak ada cakupan pengujian ✅ diperbaiki

**Berkas:** `crates/bee_cli/src/main.rs`
**Tingkat keparahan:** sedang

Ditambahkan **9** pengujian unit parsing argumen CLI yang mencakup semua subperintah:

- `test_new_command` — pembuatan proyek
- `test_generate_controller` / `test_generate_model` — pembuatan kode
- `test_run_command` / `test_run_watch` — server pengembangan
- `test_migrate_up` / `test_migrate_down` — migrasi basis data
- `test_pack_default_target` / `test_pack_custom_target` — pengemasan dan penempatan

### D. Router/RouteGroup tanpa komentar dokumentasi ✅ diperbaiki

**Berkas:** `crates/bee_router/src/router.rs:5,44`
**Tingkat keparahan:** rendah

Komentar dokumentasi ditambahkan untuk struktur `Router` dan `RouteGroup`.

### E. redis_store — clone MultiplexedConnection yang tidak perlu ✅ dianalisis

**Berkas:** `crates/bee_kv/src/redis_store.rs`
**Tingkat keparahan:** rendah

Analisis mengonfirmasi: `redis::Cmd::query_async` memerlukan referensi `&mut`, dan `self.conn.clone()` adalah penggunaan standar crate redis-rs. `MultiplexedConnection::clone()` hanya menambah hitungan referensi dengan biaya sangat kecil. **Tidak perlu perubahan.**
