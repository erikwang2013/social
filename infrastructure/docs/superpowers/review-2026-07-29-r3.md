## 第三轮发现并修复的问题（3 项）

### 1. [严重] bee_kv/redis_store — redis-rs 0.27.6 API 变更导致 `--all-features` 编译失败

**文件：** `crates/bee_kv/src/redis_store.rs`（9 处）
**严重程度：** 严重 — `--all-features` 编译失败

redis-rs 0.27.6 中 `redis::Cmd::query_async()` 签名从 `&self` 改为 `&mut self`。`RedisStore` 中全部 9 个方法使用了 `&self.conn.clone()`，需要改为 `&mut self.conn.clone()`。

**影响方法：** `get`、`set`、`del`、`exists`、`incr` (2)、`expire`、`mget`、`mset`

**修复：**
```rust
// 修复前
.query_async(&self.conn.clone())
// 修复后
.query_async(&mut self.conn.clone())
```

### 2. [中] bee_router/filter — SessionFilter 空实现无文档说明

**文件：** `crates/bee_router/src/filter.rs:17-19`
**严重程度：** 中 — 用户可能误以为 session 已被加载

`SessionFilter` 实现 `Filter` trait 但使用默认空实现（`before`/`after` 直接返回 `Ok(())`）。用户调用此 filter 后可能以为 session 已从请求中加载，但实际上并未发生。

**修复：** 更新文档注释，明确说明当前为占位实现，session 由 `Context::new()` 按请求创建。

### 3. [低] bee_template — `_to_json_value` 静默吞噬序列化错误

**文件：** `crates/bee_template/src/lib.rs:92`
**严重程度：** 低 — 仅在 `context!` 宏内部使用

```rust
// 修复前：序列化失败时静默返回 Null
serde_json::to_value(val).unwrap_or(serde_json::Value::Null)

// 修复后：panic 并给出明确错误信息（符合「程序员错误应该 panic」原则）
serde_json::to_value(val).expect("context! macro values must be serializable")
```

## 总结

第三轮审查主要发现 redis-rs 0.27.6 API 变更导致的 `--all-features` 编译失败（影响所有 9 个 KV 操作方法），以及 SessionFilter 空实现缺少文档说明。所有问题已修复，全部 63 个测试通过，clippy 零警告。

同期完成了 security-rust（v1.0.4）攻击检测库的集成：通过 `SecurityFilter` 实现 `Filter` trait，在请求进入 Controller 前扫描 URI query string 和关键 headers，覆盖 XSS、SQL 注入、命令注入、SSRF、路径遍历等 27 种攻击类型。新增 6 个安全检测测试，通过 `security` feature gate 控制。

项目整体质量良好：零 unsafe 代码、完整的错误处理、规范统一的命名、所有公共 API 有文档、每个 trait 有测试。4 个已知限制（P2/P3 级别）不影响当前功能，建议在后续版本中改进。
