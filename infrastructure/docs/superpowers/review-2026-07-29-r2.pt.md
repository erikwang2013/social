## Correções da primeira rodada (8 itens)

### 1. bee_kv — palavra-chave `mut` desnecessária (aviso de compilação)

**Arquivo:** `crates/bee_kv/src/lib.rs:129,136,145,158`
**Gravidade:** baixa

Todos os métodos de `StubKvStore` são chamados via `&self` (Mutex internamente), então `let mut store` nos testes não precisa de `mut`. Alterado para `let store`.

### 2. bee_router — `unwrap()` em `into_response()` poderia causar pânico

**Arquivo:** `crates/bee_router/src/context.rs:119`
**Gravidade:** média

`builder.body(...).unwrap()` — embora os valores de cabeçalho sejam construídos internamente e não contenham caracteres inválidos, isso viola a regra «sem panic no código de bibliotecas». Alterado para `expect()` com um comentário SAFETY explicando o motivo.

### 3. bee_router — campo `query_map` não utilizado

**Arquivo:** `crates/bee_router/src/context.rs:22`
**Gravidade:** baixa

O campo `query_map: HashMap<String, String>` foi declarado com `#[allow(dead_code)]` mas nunca usado. Removido segundo o princípio YAGNI.

### 4. bee_logs — conflito de inicialização repetida do subscriber tracing nos testes

**Arquivo:** `crates/bee_logs/src/lib.rs:100-116`
**Gravidade:** média

`test_logger_stdout` e `test_logger_default` chamam ambas `init()`, e `tracing_subscriber::try_init()` só pode ter sucesso uma vez globalmente. Usado `std::sync::Once` para garantir inicialização única, e adicionado o teste `test_level_str` para cobrir o método `level_str()`.

### 5. bee_tsdb — 3 `map_or` simplificáveis (Clippy)

**Arquivo:** `crates/bee_tsdb/src/lib.rs:198,199,200-203`
**Gravidade:** baixa

```rust
// Antes da correção
p.tags.get(&f.key).map_or(false, |v| v == &f.value)
// Depois da correção
p.tags.get(&f.key) == Some(&f.value)
```

### 6. bee_graph — `for_kv_map` simplificável para `values()` (Clippy)

**Arquivo:** `crates/bee_graph/src/lib.rs:241`
**Gravidade:** baixa

`for (_eid, edge) in emap.iter()` → `for edge in emap.values()`

### 7. bee_rust — `needless_question_mark` (Clippy)

**Arquivo:** `crates/bee_rust/src/lib.rs:37`
**Gravidade:** baixa

`Ok(bee_logs::Logger::new().init()?)` → `bee_logs::Logger::new().init()`

### 8. bee_router — trait Filter sem comentários de documentação

**Arquivo:** `crates/bee_router/src/filter.rs:4`
**Gravidade:** baixa

Adicionados comentários de documentação ao trait `Filter`.

## Correções da segunda rodada — todos os pontos ABCDE tratados (5)

### A. bee_orm — risco de injeção SQL em `to_sql()` ✅ corrigido

**Arquivo:** `crates/bee_orm/src/lib.rs:63`
**Gravidade:** alta (potencial)

`to_sql()` concatena diretamente strings brutas no SQL. Adicionado um **Warning** no comentário de documentação do método: ele serve apenas para depuração e testes, e os drivers de backend devem usar consultas parametrizadas.

### B. bee_config_macro — `unwrap_or` engolindo silenciosamente erros de análise ✅ corrigido

**Arquivo:** `crates/bee_config_macro/src/lib.rs:21-27`
**Gravidade:** baixa

`unwrap_or` alterado para `unwrap_or_else`, com comentários ampliados: valores não JSON (como `dev`, `localhost`) caem corretamente para strings JSON; se um valor contiver erro de digitação (como `8o8o`), ele é armazenado como string e `serde_json::from_value` produz um erro claro de incompatibilidade de tipos.

### C. bee_cli — sem cobertura de testes ✅ corrigido

**Arquivo:** `crates/bee_cli/src/main.rs`
**Gravidade:** média

Adicionados **9** testes unitários de análise de argumentos CLI cobrindo todos os subcomandos:

- `test_new_command` — criação de projeto
- `test_generate_controller` / `test_generate_model` — geração de código
- `test_run_command` / `test_run_watch` — servidor de desenvolvimento
- `test_migrate_up` / `test_migrate_down` — migrações de banco de dados
- `test_pack_default_target` / `test_pack_custom_target` — empacotamento e implantação

### D. Router/RouteGroup sem comentários de documentação ✅ corrigido

**Arquivo:** `crates/bee_router/src/router.rs:5,44`
**Gravidade:** baixa

Adicionados comentários de documentação às estruturas `Router` e `RouteGroup`.

### E. redis_store — clone desnecessário de MultiplexedConnection ✅ analisado

**Arquivo:** `crates/bee_kv/src/redis_store.rs`
**Gravidade:** baixa

A análise confirmou: `redis::Cmd::query_async` exige uma referência `&mut`, e `self.conn.clone()` é o uso padrão da crate redis-rs. `MultiplexedConnection::clone()` apenas incrementa o contador de referências, com custo desprezível. **Nenhuma alteração necessária.**
