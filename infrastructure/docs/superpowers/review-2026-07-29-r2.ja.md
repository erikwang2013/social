## 第 1 ラウンドの修正（8 件）

### 1. bee_kv — 不要な `mut` キーワード（コンパイル警告）

**ファイル:** `crates/bee_kv/src/lib.rs:129,136,145,158`
**深刻度:** 低

`StubKvStore` の全メソッドは `&self` で呼び出されるため（内部は Mutex 使用）、テストの `let mut store` に `mut` は不要です。`let store` に変更しました。

### 2. bee_router — `into_response()` の `unwrap()` が panic を起こす可能性

**ファイル:** `crates/bee_router/src/context.rs:119`
**深刻度:** 中

`builder.body(...).unwrap()` — ヘッダー値は内部生成のため不正文字は含まれませんが、「ライブラリコードでの panic 禁止」ルールに違反します。理由を説明する SAFETY コメント付きの `expect()` に変更しました。

### 3. bee_router — 未使用の `query_map` フィールド

**ファイル:** `crates/bee_router/src/context.rs:22`
**深刻度:** 低

`query_map: HashMap<String, String>` フィールドは `#[allow(dead_code)]` 付きで宣言されていましたが、一度も使用されていませんでした。YAGNI 原則に従い削除しました。

### 4. bee_logs — テストでの tracing subscriber 重複初期化の競合

**ファイル:** `crates/bee_logs/src/lib.rs:100-116`
**深刻度:** 中

`test_logger_stdout` と `test_logger_default` がどちらも `init()` を呼び、`tracing_subscriber::try_init()` はグローバルに一度しか成功できません。`std::sync::Once` で一度だけ初期化されるようにし、`level_str()` メソッドをカバーする `test_level_str` テストを新設しました。

### 5. bee_tsdb — `map_or` 3 箇所を簡略化可能（Clippy）

**ファイル:** `crates/bee_tsdb/src/lib.rs:198,199,200-203`
**深刻度:** 低

```rust
// 修正前
p.tags.get(&f.key).map_or(false, |v| v == &f.value)
// 修正後
p.tags.get(&f.key) == Some(&f.value)
```

### 6. bee_graph — `for_kv_map` を `values()` に簡略化可能（Clippy）

**ファイル:** `crates/bee_graph/src/lib.rs:241`
**深刻度:** 低

`for (_eid, edge) in emap.iter()` → `for edge in emap.values()`

### 7. bee_rust — `needless_question_mark`（Clippy）

**ファイル:** `crates/bee_rust/src/lib.rs:37`
**深刻度:** 低

`Ok(bee_logs::Logger::new().init()?)` → `bee_logs::Logger::new().init()`

### 8. bee_router — Filter trait にドキュメントコメントがない

## 第 2 ラウンドの修正 — ABCDE すべて対応（5 件）

### A. bee_orm — `to_sql()` の SQL インジェクションリスク ✅ 修正済み

**ファイル:** `crates/bee_orm/src/lib.rs:63`
**深刻度:** 高（潜在）

`to_sql()` は生文字列を直接 SQL に連結します。メソッドのドキュメントコメントに **Warning** を追加: 本メソッドはデバッグとテスト専用であり、バックエンドドライバは必ずパラメータ化クエリを使用すること。

### B. bee_config_macro — `unwrap_or` が解析エラーを静かに握りつぶす ✅ 修正済み

**ファイル:** `crates/bee_config_macro/src/lib.rs:21-27`
**深刻度:** 低

`unwrap_or` を `unwrap_or_else` に変更し、コメントを拡充: 非 JSON 値（`dev`、`localhost` など）は JSON 文字列に正しくフォールバックされます。値に誤字がある場合（`8o8o` など）は文字列として保存され、`serde_json::from_value` が明確な型不一致エラーを生成します。

### C. bee_cli — テストカバレッジなし ✅ 修正済み

**ファイル:** `crates/bee_cli/src/main.rs`
**深刻度:** 中

全サブコマンドをカバーする CLI 引数パースのユニットテスト **9 個**を追加しました:

- `test_new_command` — プロジェクト作成
- `test_generate_controller` / `test_generate_model` — コード生成
- `test_run_command` / `test_run_watch` — 開発サーバー
- `test_migrate_up` / `test_migrate_down` — データベースマイグレーション
- `test_pack_default_target` / `test_pack_custom_target` — パッケージング・デプロイ

### D. Router/RouteGroup にドキュメントコメントがない ✅ 修正済み

**ファイル:** `crates/bee_router/src/router.rs:5,44`
**深刻度:** 低

`Router` と `RouteGroup` 構造体にドキュメントコメントを追加しました。

### E. redis_store — MultiplexedConnection の不要な clone ✅ 分析済み

**ファイル:** `crates/bee_kv/src/redis_store.rs`
**深刻度:** 低

分析で確認: `redis::Cmd::query_async` は `&mut` 参照を必要とし、`self.conn.clone()` は redis-rs crate の標準的な使い方です。`MultiplexedConnection::clone()` は参照カウントを増やすだけで、オーバーヘッドは極めて小さい。**変更不要。**
