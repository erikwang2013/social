## Issue List

### 1. 🔴 Invalid configuration item in the root Cargo.toml

**File**: `Cargo.toml:24`  
**Issue**: `name = "bee-rust"` in `[workspace.package]` is an invalid key, producing a warning on every compilation:

```
warning: /home/wwwroot/bee-rust/Cargo.toml: unused manifest key: workspace.package.name
```

**Fix**: Remove the `name = "bee-rust"` line. A workspace-level package does not need a name; only each sub-crate's `[package]` needs one.

---

### 2. 🔴 Missing LICENSE file

**Issue**: The root `Cargo.toml` declares `license = "Apache-2.0"`, but there is no `LICENSE` file in the repository root. The Apache-2.0 license terms require that a copy of the license be included in distributions.

**Fix**: Create a `LICENSE` file in the root directory containing the full text of the Apache-2.0 license.

---

### 4. 🟡 Missing crates.io publication metadata

All crates lack the following fields, which hurts discoverability on crates.io:

- `description` — brief description
- `repository` — repository link
- `keywords` — search keywords
- `categories` — categories (e.g. `["web-programming", "database"]`)

It is recommended to add common fields to `[workspace.package]`:

```toml
[workspace.package]
repository = "https://github.com/erikwang2013/bee-rust"
keywords = ["web", "framework", "beego", "mvc"]
categories = ["web-programming"]
```

### 6. 🟡 Storage engine features are empty placeholders

The following features are declared but have no actual implementation, serving only as empty placeholders:

- `bee_search`: `elasticsearch`, `opensearch`, `clickhouse` are all `[]`
- `bee_graph`: `neo4j`, `nebulagraph`, `arangodb` are all `[]`
- `bee_tsdb`: `influxdb`, `iotdb`, `questdb` are all `[]`

This means the code examples for search engines, graph databases, and time-series databases shown in the README cannot actually run (their tests also use stubs).

**Suggestion**: Mark these features as "planned" in the README, or add actual driver dependencies and implementations.

---

### 7. 🟡 StubKvStore::expire() is a no-op

**File**: `crates/bee_kv/src/lib.rs:111`  
**Issue**: The `expire()` method of the test stub `StubKvStore` does not implement TTL expiration logic, even though the trait defines this interface. This means tests cannot cover TTL-related behavior.

---

### 8. 🟢 Redundant cfg annotation on RedisStore

**File**: `crates/bee_kv/src/redis_store.rs`  
**Issue**: The entire module is already conditionally compiled via `#[cfg(feature = "redis")]` in `lib.rs`, so the `#[cfg(feature = "redis")]` annotation inside `redis_store.rs` is redundant (functionally correct, but not concise).

---

### 9. 🟢 Missing doc-tests

Apart from `bee_template`, which has 1 doc-test, none of the other crates have documentation tests. It is recommended to add doc-test examples for the core traits (`Cache`, `KvStore`, `Controller`, etc.).

---

### 10. 🟢 bee_graph/src/lib.rs is somewhat large

406 lines, close to the 500-line limit. Splitting is recommended later (e.g. separate model.rs, query.rs).

## Summary

The overall code quality of the project is good: compilation passes, tests are all green, Clippy reports zero warnings, and there is zero unsafe code. The architecture is clear and the trait abstractions are reasonable. The main problems are concentrated in **ecosystem configuration completeness** — missing license files, incomplete Cargo.toml metadata, and no CI/CD or formatting configuration. These issues do not affect functionality, but they do affect the professionalism of the open-source project and the crates.io publishing experience. It is recommended to fix the P0 and P1 items first.
