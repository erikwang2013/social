## 3차에서 발견 및 수정된 문제 (3건)

### 1. [심각] bee_kv/redis_store — redis-rs 0.27.6 API 변경으로 `--all-features` 컴파일 실패

**파일:** `crates/bee_kv/src/redis_store.rs` (9곳)
**심각도:** 심각 — `--all-features` 컴파일 실패

redis-rs 0.27.6에서 `redis::Cmd::query_async()`의 시그니처가 `&self`에서 `&mut self`로 변경되었습니다. `RedisStore`의 전체 9개 메서드가 `&self.conn.clone()`을 사용하므로 `&mut self.conn.clone()`로 변경해야 합니다.

**영향 메서드:** `get`, `set`, `del`, `exists`, `incr` (2), `expire`, `mget`, `mset`

**수정:**
```rust
// 수정 전
.query_async(&self.conn.clone())
// 수정 후
.query_async(&mut self.conn.clone())
```

### 2. [중간] bee_router/filter — SessionFilter 빈 구현에 문서 설명 없음

**파일:** `crates/bee_router/src/filter.rs:17-19`
**심각도:** 중간 — 사용자가 session이 로드되었다고 오해할 수 있음

`SessionFilter`는 `Filter` trait을 구현하지만 기본 빈 구현(`before`/`after`가 바로 `Ok(())` 반환)을 사용합니다. 사용자는 이 필터를 호출한 후 session이 요청에서 로드되었다고 생각할 수 있지만 실제로는 아무 일도 일어나지 않습니다.

**수정:** 문서 주석을 업데이트하여 현재는 자리 표시자 구현이며 session은 `Context::new()`가 요청별로 생성함을 명확히 설명합니다.

### 3. [낮음] bee_template — `_to_json_value`가 직렬화 오류를 조용히 삼킴

**파일:** `crates/bee_template/src/lib.rs:92`
**심각도:** 낮음 — `context!` 매크로 내부에서만 사용

```rust
// 수정 전: 직렬화 실패 시 조용히 Null 반환
serde_json::to_value(val).unwrap_or(serde_json::Value::Null)

// 수정 후: 명확한 오류 메시지와 함께 panic ("프로그래머 오류는 panic이어야 한다" 원칙)
serde_json::to_value(val).expect("context! macro values must be serializable")
```

### 알려진 제한 사항 (후속 버전에서 개선 권장)

| # | 위치 | 설명 | 우선순위 |
|---|------|------|--------|
| 1 | `bee_router/router.rs` | `Handler<T, ()>`가 `()` 타입 매개변수를 사용하여 handler가 axum extractor(State/Query/Path 등)를 사용할 수 없음 | P2 |
| 2 | `bee_config_macro` | `reload()`와 `watch()`가 빈 구현을 생성하며, trait 문서의 "다시 로드" 및 "변경 감시" 설명과 불일치 | P2 |
| 3 | `bee_rust/prelude` | `bee_config::Config`를 내보내는 것은 derive 매크로이지 `ConfigSource` trait이 아니므로 명명이 혼란을 줄 수 있음 | P3 |
| 4 | `bee_orm/QuerySet` | `T` 제네릭에 trait bound가 없고 `PhantomData<T>`는 타입 표시로만 사용 | P3 |

### 긍정적 평가

- **오류 처리:** 모든 crate가 `thiserror::Error` 파생을 사용하며 오류 타입 정의가 명확함
- **Feature gate:** `bee_kv/redis_store`가 `#[cfg(feature = "redis")]`를 올바르게 사용
- **테스트 커버리지:** 모든 trait에 대응하는 stub 구현과 테스트가 있음
- **문서:** 모든 공개 타입과 trait 메서드에 `///` 문서 주석이 있음
- **비동기 안전성:** `tokio::sync::RwLock`을 올바르게 사용하며 비동기 컨텍스트에 블로킹 호출이 섞이지 않음
- **unsafe 코드 없음:** 프로젝트 전체에서 unsafe 0건
- **unwrap 없음:** 라이브러리 코드에는 SAFETY 주석이 있는 `expect()`만 존재

## 요약

3차 리뷰에서는 주로 redis-rs 0.27.6 API 변경으로 인한 `--all-features` 컴파일 실패(전체 9개 KV 연산 메서드에 영향)와 SessionFilter 빈 구현의 문서 설명 부재를 발견했습니다. 모든 문제가 수정되었고 전체 63개 테스트가 통과하며 clippy 경고는 0건입니다.

같은 기간에 security-rust(v1.0.4) 공격 탐지 라이브러리를 통합했습니다. `SecurityFilter`가 `Filter` trait을 구현하여 요청이 Controller에 진입하기 전에 URI query string과 주요 headers를 스캔하며, XSS, SQL 인젝션, 명령 인젝션, SSRF, 경로 탐색 등 27가지 공격 유형을 다룹니다. 보안 감지 테스트 6개를 새로 추가했고 `security` feature gate로 제어합니다.

프로젝트 전반의 품질은 양호합니다. unsafe 코드 0건, 완전한 오류 처리, 일관된 명명 규칙, 모든 공개 API 문서화, 모든 trait 테스트를 갖췄습니다. 4개의 알려진 제한 사항(P2/P3 수준)은 현재 기능에 영향을 주지 않으며 후속 버전에서 개선을 권장합니다.
